## 架构文档

默认扁平模块文件，工程级约束集中于 engineering.md。公开行为在现役 spec 权威维护，模块文档链接它，并解释必要机制。
所有权、生命周期、失效条件、失败后状态、线程与同步约束以及影响正确性的不变量不得省略；不为去重删掉工程知识。
简单类型共用章节，显然函数和字段不逐项抄录。仅复杂独立契约或明显妨碍模块阅读时拆出笔记。
不维护逐类/逐函数学习版，不为未实现模块建空文档。稳定不变量编号保留；源码审阅不冒充运行、线程安全或性能已验证。
当前模块按架构入口定位；只随获授权变更修订受影响内容，不因文档整理扩大功能实施或重选架构。

## Spec 与决策

轻量 symocraft-lite 只有 proposal 和必要 delta specs：短设计及唯一任务清单在 proposal.md。
复杂 symocraft-full 使用 proposal、delta specs、design、tasks；不再维护额外阶段 spec/active/总结链。
proposal 写意图、范围和依赖；design 写目标机制；tasks 维护一份按意图和依赖组织的活动计划。
行为增量使用原生 ADDED/MODIFIED/REMOVED/RENAMED；Requirement 用 SHALL/MUST，Scenario 用 WHEN/THEN。
MODIFIED 保留完整 requirement 及全部继续有效 scenarios；无行为变化使用 skip_specs: true，不编造游戏需求。
现役 specs 只接纳经核对的已实现契约；目标不能因设计定稿、planningComplete 或任务打勾变成现役行为。
重要决策按需要在同一 change 的 decisions.md 集中，保留选择、理由、代价、适用范围和稳定任务限定编号。
不为每个小步骤建立 change 或 ADR；跨阶段链接原决策，改变时注明替代关系，不重选既定方案。
已实现选择的长期理由可在当前模块机制中保留；点时批准依据留冻结材料，不把已完成旧计划重新变成活动任务。

## 文档预算与表达

| 类型 | 默认动作 |
| --- | --- |
| S 局部修复 | 不新建文档/change，仅修正失效说明；行为契约改变按 M |
| M 普通功能 | 轻量 change，同步受影响模块，不另建计划或总结 |
| L 复杂任务 | 一个完整 change、一份必要任务清单 |
| D 重要决策 | 权威位置记录长期理由，不默认逐条 ADR |
| A 验证归档 | 每个 change 一份 verification.md，默认无附件、不附原始数据；随 change 归档 |

类型可组合但不重复内容；验收也受预算管理，不享无限文件例外。
不要求固定模板章节、公开/私有函数表或“不适用”占位。schema 内最小生成模板仅为工具输入，不恢复旧学习模板/示例。
日常结果在聊天汇报，必要验证结论更新同一 change 的 verification.md；不默认生成 Summary、逐步实施日志或独立测试报告。默认更新已有文档；新建前明确用途、归属与生命周期。

## 验证与批准

全局 VERIFICATION.md 仅保留关键节点批准和导航；节点仅为设计冻结、正式实施入口、阶段整体验收通过。具体方法、结果、失败和未覆盖项在对应 change 的 verification.md 维护，不复制成全局验证正文或平行台账。
日常子步骤不建立独立批准记录，但不因此扩大实施范围或取消权限。仅凭用户明确确认登记批准，三个节点不互相推定。
源码审阅、自动测试、真实运行、性能测量、人工批准与 Obsidian 同步分别记录。OpenSpec status/validate/verify 不替代工程验证。
测试按改动影响范围选择最小充分集合，避免逐步重复或默认全量回归；仅在阶段交付、广泛影响或范围不明时扩大验证。既定验收要求不变，未执行项如实说明。需要新增阶段测试矩阵时，先在聊天提出建议，由用户确认规划与执行范围，不默认创建或执行。
真实 sync/archive 前核对本轮授权、适用验证与阶段依据；归档通常也会合并规格，不能用未完成真实任务测试生命周期。
验证记录保留必要版本、环境、配置、验证方法、实际结论和限制，不将汇总或人工反馈冒称原始数据。旧冻结材料保留点时含义、原字节及哈希，不改历史来源字段、命令、结果或批准。

### 每个 change 一份验证记录

2026-10-12 用户确认：每个 change 的验证正文统一保存在 `docs/openspec/changes/<change>/verification.md`，不按步骤、运行或重试拆文件。该文件只维护必要验证结论，不成为执行流水账、第二任务清单或人工批准台账；无需固定模板或“不适用”占位。
默认无附件；无特别要求不附原始数据，包括整段日志、逐帧数据、截图、源码快照、运行包和独立清单。日常工作产物留在 out 或原工作位置，不为验证归档再复制，也不强制新增 verification/archive 目录或压缩包。
特别要求仅指用户明确要求，或适用规格/已确认验收协议明确规定的原始数据留存、复算或交付要求；一般“有复现价值”不自动构成例外。存在例外时在同一 verification.md 说明依据和准确范围，优先引用已有材料；确需新增附件时仅保存要求覆盖的最小充分集合，置于同一 change 的浅层 evidence/，不嵌套完整来源目录、不另建总结/索引链。不复制已有旧冻结证据。
不附原始数据只改变默认长期保存方式，不取消实际测试、采集、统计校验、既定验收门槛或已明确要求的原始数据留存。未执行、失败、禁用、缺失及不可复算范围如实记录，不从短测、汇总或任务勾选推定正式通过。
verification.md 及明确要求的附件随 change 目录一并移入 `docs/openspec/changes/archive/<date>-<change>/`；全局 VERIFICATION.md 仅更新导航和适用关键节点批准。归档不自动授权 spec sync、实施、验收或 Git 写入。

### 旧冻结证据保持

既有 `docs/verification/archive/`、历史 evidence/out、已归档 change 和其清单暂时不动，不追溯补建 verification.md，不重打包、搬移、重命名、裁剪或删改冻结材料。既有历史命令、来源身份、稀疏/负向状态及结果保持原义；当前可维护索引可以改为导航，不据此声称旧包已恢复或重新验证。
后续若另获准确迁移/清理授权，须保持原字节、大小和 SHA256，登记位置映射并核对引用/消费者与恢复；获确认的准确清单之外不删除。迁移失败、未判明材料、未提交唯一输入、当前候选、必要完整运行包及暂停任务现场保留，验证摘要不替代它们。
验证记录及获要求保存的附件不加入 Git 忽略规则；提交/上传和远端恢复仍需分别验证并另获 Git 授权，不能仅凭归档位置宣称远端保存。必要材料无法保存时先报告缺口，不静默省略或删除唯一包。
旧 archive 的 Obsidian Sync 排除约定不等于 Git 忽略或本地删除；Agent 不修改 Obsidian 配置，不冒称同步设置已验证。新规则不自动授权搬移、删除、采样、真实 sync/archive 或 Git 写入。

## 标签与检查

可维护 docs 笔记保留一个 area/* 归属标签，topic/* 按需要使用。OpenSpec 规格归 area/spec，治理归 area/meta。
schema 生成模板不是可维护知识笔记；冻结 evidence 与 verification/archive 不批量补标签。
标签清单 [tag-inventory.json](tag-inventory.json) 是生成查找辅助，不是第二份规则。由 `python tools/openspec/check_documents.py --write-index` 显式刷新；私有注册只保留已有索引信息，不读取正文。旧清单保留历史计数，Obsidian 配置与 UI 结论不覆盖。
检查路径、入出链、锚点、图片、源码引用、权威重复、契约身份、冻结字节与非文档差异；机械检查不代替语义审阅。

历史证据已压缩时，现役链接指向实际归档包，并用链接标题保留准确成员路径。检查器保持原迁移索引不变，通过系统 libarchive tar（Windows 自带 tar.exe）只读流式核验登记成员的大小/SHA256，不在仓库恢复散文件；已退役复核源按 VERIFICATION 记录的固定 Git 提交核验原字节。缺工具、缺成员、内容不符或无法核对退役原文仍报错，不扩大历史路径豁免，也不把包完整性核验当运行或历史缺项通过。
