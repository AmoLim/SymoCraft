# 开发自动化脚本规范

- **语言分工**：生产代码、核心算法和原生单元测试使用项目规定可用语言；文件处理、代码生成、批量修改、工具编排、集成测试辅助和数据分析默认使用 Python 3。不得仅为自动化方便将原生逻辑移入 Python。

- **沿用项目工具链**：优先使用项目已有的 CMake、Presets、CTest 和 C++ 测试框架。构建目标、依赖、编译选项及安装规则由 CMake 管理，Python 不重复实现构建系统。

- **按复杂度选择入口**：简单、单次的 CMake、Git、编译器或测试命令可以直接执行；需要条件判断、重复运行、文件处理、日志归档或错误恢复时，优先使用 Python 编排，避免为单条命令创建额外脚本。

- **Python 依赖**：遵守项目明确记录的最低 Python 版本，优先使用 `pathlib`、`shutil`、`subprocess`、`json`、`argparse`、`unittest` 等标准库。新增第三方依赖必须有明确必要性，并记录用途和安装要求。

- **外部工具调用**：Python 默认通过 `subprocess.run()` 调用外部工具，使用参数列表和 `shell=False`，明确工作目录、返回码检查及必要的超时。持续采样或需要取消的任务可使用 `subprocess.Popen()`，并清理自己启动的进程。

- **限制 shell 逻辑**：不新增 PowerShell（`.ps1`）脚本，除非确实依赖其专有功能。PowerShell、cmd 或其他 shell 可以作为启动入口，或用于加载厂商提供的工具链环境，但业务逻辑和自动化逻辑由 Python 实现。

- **修改与解析**：手工代码修改优先使用精确补丁；规则明确、可重复的批量变更可使用 Python。结构化数据使用对应解析器；涉及 C++ 语法、符号或接口的复杂修改，优先使用编译器或语法感知工具，不依赖宽泛文本替换。

- **代码生成**：生成过程应可复现，明确输入、输出和依赖；需要参与构建时接入 CMake 的生成规则。避免每次构建无条件重写文件，保证增量构建正确。

- **测试职责**：C++ 单元与契约测试继续使用原生测试框架，并由 CTest 统一执行；Python 用于进程级验证、测试夹具、结果校验和报告。不得用 Python 模拟结果替代真实编译、原生测试或硬件验证。

- **路径与证据安全**：正确处理空格、Unicode 和不同路径分隔符；明确相对路径基准。不得覆盖已有验证证据、删除用户文件或撤销已有工作区修改；删除操作须先校验目标范围。二进制文件和 Git 补丁按字节处理。

- **跨平台边界**：通用脚本优先兼容 Windows、Linux 和 macOS，平台相关实现应集中隔离。MSVC、Windows SDK、特定图形后端等专用流程可以限定平台，但必须明确说明；不得为追求表面兼容而改变项目工具链或行为。

- **失败与验证**：工具失败、测试失败和证据无效必须明确返回非零状态并保留诊断，不静默忽略。测试范围与修改风险相匹配；未验证的平台、硬件和构建配置必须如实标注。
