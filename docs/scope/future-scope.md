# 后续范围与待选方案

用户已确认 T4 保持零物理步时的现有跳跃语义：已接受的跳跃在角色规则阶段生效，位置等待正常物理子步推进；具体契约与旧新对照由 [T4 正式计划](../openspec/changes/archive/2026-10-19-m3-t4-application-simulation/design.md) 和 A08 维护。后续若调整角色输入手感，再确认是否以及如何暂存玩法意图。本项不改变 T2 的按键短按锁存，也不重新选择 D07 的自有 InputFrame 交接。

### 正式选型前需确认

- 缓冲对象与范围：先明确是否仅处理跳跃；不自动扩展到连续移动、选材、编辑或攻击。
- 时序与前提：请求接收、跳跃条件检查及速度修改发生在哪个阶段；与零/多物理步、长帧裁剪、短按和 held 输入如何配合，不能因多子步重复触发。
- 存储与有效期：由会话控制器拥有；确认时间依据、容量、覆盖/合并、过期及消费规则，不使用渲染帧数或图形状态作为隐含运行前提。
- 清除与恢复：暂停/恢复、失焦策略、sensor 切换、玩家恢复与会话失败时的处理，避免恢复后补触发旧请求。
- 行为边界：落地前预输入仅属于候选方案3的可能能力；离地宽限改变跳跃前提，须单独确认，不随输入缓冲自动引入。
- 验收与进入条件：同意图/时间序列下比较零/单/多步、连续短按、落地前按键、过期与恢复行为；保留当前基线，确认手感变化和实际成本后另立 spec，并取得实施授权。

### 评估触发条件

满足以下任一条件时启动评估，而不是自动采用方案3：

- 多个真实推进入口或中立消费者之间出现可复现的秒/毫秒混用、原始时间与裁剪时间混用、重复归一化或校验遗漏，且仅靠现有会话边界与明确命名不足以稳定约束；保留出错输入、调用链及影响证据。
- 真实调度/计算消费者明确需要复用并跨入口传递同一份已校验时间，以类型限制单位、合法范围及裁剪策略来源；现有显式数值接口无法满足已确认的接口约束，先给出消费者与数据流，不因抽象偏好引入类型。

新增一个CPU调用方、实体数量增加、仅计划拆进程或看到重复数值参数，不单独触发迁移。方案3是否减少错误或重复处理需用实际调用链对照；本项不是性能优化结论，不预设调用方数量、耗时或分配阈值。

### 采用前需确认

- 明确工厂输入单位、可接受范围、错误结果、裁剪策略及数值转换顺序；阻止未经校验的构造和静默单位转换，不通过默认值把失败伪装成合法零时间。
- 区分原始经过时间、有效角色规则时间和固定步预算；已校验值不能使角色/冷却改用8/120s上限，也不能替代场景实际时间或物理单步时长。若需表达多种时间，逐项确认，不扩成通用时钟框架。
- 保留D11参数拒绝不改状态、零时间仍处理规则、D04部分提交/Failed、D10暂停恢复，以及原有CPU/本地组合与观测口径；不随类型迁移增加追赶、回放或跨平台确定性承诺。
- 对比三个候选的调用约束、迁移成本及实际开销，新增类型只在消除真实错误或满足具体契约时采用；正式spec、消费者迁移和回归证据需单独审核，并取得实施授权，落实后同步实际architecture文档。

## F03 跨模块架构候选

2026-10-10 从原 OOP/DOD 初稿浓缩；不是新实施计划。已形成 T3/T4 目标分别由对应 change 维护，不重复 Application、Session、Renderer 等完整接口。
已确认的旧稿选择保持：Q1 混合设计，Q2 不预建 Engine/GameSession（确有 editor 复用再评估），Q4 精简重复玩家姿态的相机实体，Q9 不立即 SoA/并行/更换 ECS。旧稿的审核意见不升级为设计冻结或实施授权；T4 后续明确选择优先于早期候选。

### 表示与处理边界

OOP 管实际所有权、身份、生命周期与不变量；DOD 管代表性工作负载、访问模式与批数据变换，两者可共存。组件可在受控阶段原地更新，不要求纯函数、全部不可变快照或统一 System 基类。
HD-I1：批写数据有唯一权威 owner；HD-I2：借用不跨 callback/扩容/删除/重建/销毁失效点；HD-I3：角色每帧、物理每子步及基准前编辑/普通后编辑不重排；HD-I4：统计排序数值副本，不重排原帧或把缺失补0；HD-I5：布局变化不自动改变格式、生成摘要及成功版本语义；HD-I6：连续数组或内部锁不证明公共 API 线程安全。
保留 AoS 顶点、简单值和自由函数作为起点。只有代表性访问、查询/复制/传输成本成为实测瓶颈时，才评估热冷分离、AoS/SoA、View/稀疏池或替换存储；需行为等价、成本及预算证据，不由结构改善宣称 FPS 收益。

RAII 迁移必须覆盖部分构造：完整对象未构造成功不会执行其析构，已获 native 资源立即交 owner/局部 guard；组件裸指针的浅复制与析构必须一起处理，不能只补析构造成双重释放。
HD-I2 与原 R05 同时约束值、view 和 handle：复制借用/句柄不延长寿命、不转移 GPU 所有权、不允许重复 Destroy；noexcept 移动须证明真实安全。
GPU 在途回收遵循 Renderer，不因 CPU 析构立即释放。缓存 Create 成功而映射登记分配失败须撤回或可靠跟踪，清理不覆盖原错；Session 析构不 Seal/Export、宣布 completed 或删失败证据。这些不证明全部当前异常路径已安全。
