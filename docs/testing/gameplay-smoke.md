# M2 玩法冒烟验收

## 状态与范围

本文保留完整的 14 项 M2 验收用例及 15 分钟连续玩法要求，不是自动测试推导出的整体通过报告。**在 M2-A 记录时，仅取得桌面端自动测试和部分交互证据；当时 14 项综合用例、15 分钟连续玩法、性能基线和指定 Y9000P 笔记本验收尚未完成。** 构建成功或局部动作有响应不能替代整项验收。

M0 仅做过局部启动观测和一次 Release Esc 退出，见 [M0 报告](../milestones/m0/README.md)。这些历史记录保留；M2-A 当前结果与证据见 [M2-A 报告](../milestones/m2-a/README.md) 和本文的局部证据表，不用旧版本结果替代当前复测。

M2-T2 已加入 [固定 seed 与边界场景](../project/benchmark/testing/reproducible-scenes.md)，供下表用例复现位置和几何；[本项验证报告](../milestones/m2-t2/README.md) 只记录生成与有限帧验证，不改变下表的人工验收状态。

M2 目标是保住现有单机体素玩法，并得到能够正常启动、交互、退出的游戏版本。当前世界为固定的 441 个已创建区块，外围一圈不绘制，内圈最多 361 个区块参与绘制，不是无限地图。存档、联网、动态区块流式加载和完整生存系统不因本表而自动进入 M2 范围。

M0 语义基线见 [架构与数据流](../legacy/architecture/current-data-flow.md)；M2-A 当前变化见 [玩家循环](../legacy/architecture/player-loop.md) 与 [应用生命周期](../legacy/architecture/application-lifecycle.md)。重点代码为 [主循环与按键](../../game/app/src/application.cpp)、[射线编辑](../../game/modules/simulation/src/playercontroller.cpp)、[角色](../../game/modules/simulation/src/character_system.cpp)、[碰撞](../../game/modules/simulation/src/physics_system.cpp)。

2026-10-05 用户在本聊天明确确认桌面与 Y9000P 已完成完整验收。连续玩法表中的 `pass` 和项目范围的 M2-T4 勾选按此确认保留，不是本轮 Git 整理实测。下方 14 项表的逐项结果仍是 M2-A 历史记录；本次未取得新的逐项日志、版本、机器时长或资源曲线，不补造这些记录，也不由此通过后续 60 分钟稳定性或 M3-T0 整体验收。

## M2：15 分钟连续玩法

开始计时前已经成功进入可操作世界；加载耗时单独记录。以下步骤连续运行至少 15 分钟，不用重启绕过异常。可先完成上表其余用例，再执行本段。

| 时间段      | 场景                | 观察项                    | 当前结果 |
| -------- | ----------------- | ---------------------- | ---- |
| 0-3 分钟   | 步行、奔跑、转向、跳跃、落地    | 输入、碰撞、帧时间与内存起始值        | pass |
| 3-7 分钟   | 重复拆放、切换材料、连续操作    | 编辑反馈、网格重建卡顿、错误日志       | pass |
| 7-10 分钟  | 正负坐标区块交界与墙角交互     | 裂缝、旧面残留、错误坐标、碰撞一致性     | pass |
| 10-12 分钟 | 改变窗口尺寸、切出和恢复      | 恢复是否及时、输入是否失控          | pass |
| 12-15 分钟 | 回到先前场景继续操作，末尾静止观察 | 画面和玩法仍正常；比较相近场景的内存及帧时间 | pass |

通过条件：无崩溃、卡死、世界损坏或阻止继续游玩的故障；正常退出；日志中的错误均有解释和处置。帧时间、内存峰值与变化需记录，但未约定硬件、场景和预算前，不用任意 FPS/内存数字宣布“工程级性能达标”。

15 分钟通过只证明短程稳定性，不证明不存在泄漏。未执行、受阻或出现异常的项目必须保留在结果摘要中。

## 后续：60 分钟稳定性

这是后续稳定性验收，不与 M2 的 15 分钟合并计时，也不能由 M2 通过推定通过。

| 用例 | 操作与观测 | 通过依据 | 当前结果 |
| --- | --- | --- | --- |
| ST-60 长时间循环 | 连续 60 分钟重复移动、编辑、交界、静止和窗口恢复；每 5 分钟记录相同场景的内存、帧时间与错误数 | 无崩溃、卡死和世界损坏；相同场景资源使用无无法解释的持续增长；性能符合届时约定预算 | 未执行 |
| ST-RESTART 重启循环 | 多次启动、进入、操作、正常退出，记录次数和退出状态 | 无偶发启动/退出故障；资源检查无未解释问题 | 未执行 |

若未来加入动态区块卸载、保存/加载或异步网格，应新增对应生命周期、取消任务和旧结果丢弃用例。当前这些能力未接入主循环，不把它们列为现有实现的已通过功能。

## 结果填写规则

完整执行的项目写“通过”或“失败”；未执行或只做了部分操作的项目写“未执行（原因）”或“未完整验收（已做部分及缺项）”，并附证据路径。修复后的复测应引用原失败记录。建议结果摘要分别列出构建结果、启动结果、功能结果、15 分钟结果和后续 60 分钟结果，避免一个“测试通过”掩盖范围差异。
