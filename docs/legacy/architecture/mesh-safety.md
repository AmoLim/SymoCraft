# 区块网格与批次内存安全

> 历史架构参考：M2-A。文中的“当前”指该阶段，不代表最新实现；归档不表示相关机制全部废弃。源码链接保留定位用途，不固定历史版本或行号。参见 [历史架构索引](README.md)；后续设计约定见 [项目范围](../../spec/project-scope.md)，不据此推定重构已经完成。

## 阶段与边界

本模块属于 M2-A，目标是消除现有固定世界初始化、CPU 网格生成和 GPU 批次提交中的所有权与越界风险。不新增动态区块加载、异步生成、剔除算法、网格压缩或渲染线程。

主要实现文件：

- `include/world/chunk.h`、`src/world/chunk.cpp`
- `src/world/chunk_manager.cpp`
- `include/renderer/batch.hpp`

实际验证结果、编译器与运行条件以 [M2-A 主报告](../../milestones/m2-a/README.md) 为准，下述测试条目说明覆盖范围，不单独代表执行通过。

## 原问题与处理

| 原问题 | 本次处理 | 约束与结果 |
| --- | --- | --- |
| 区块顶点计数为 `uint16`，复杂网格超过 65,535 后回绕 | 顶点数由 `std::vector<BlockVertex3D>::size()` 提供，`VertexCount()` 返回 `size_t` | 不再维护第二份易失配的 16 位计数 |
| 每次生成固定大小缓冲，先写入后判断越界 | 使用 `vector::insert` 追加完整面，容器在写入前完成容量增长 | 分配失败以标准异常上报，不继续使用失效缓冲 |
| `AmoMemory_ReAlloc` 返回值未接回，原指针可能悬空 | 网格路径不再使用裸 `realloc` | 数据由容器独占管理 |
| `Chunk` 裸指针可浅拷贝，生成循环曾复制区块 | 方块与顶点缓冲改为 `vector`，禁止复制，允许移动；管理器使用 `try_emplace` | 生成与遍历必须通过引用；节点容器中已连接邻居的区块不应被外部移动 |
| 缺邻居时读/删解引用空指针，写入可能继续使用越界局部下标 | 先判断高度及有效存储；水平越界按方向转交邻居，没有邻居立即失败 | 读返回 `NULL_BLOCK`，写与删返回 `false` |
| `FreeAllChunks` 仅释放缓冲，保留容器中的失效对象 | 改为 `chunks.clear()`，由区块容器成员自动释放 | 连续清理后可重新创建区块集合，不代表完整重开世界 |
| 邻居重建只设置边缘标记、不清除旧标记 | 每次完整重算 `m_is_fringe_chunk` | 从孤立状态补齐邻居后不会永久保持旧标记 |
| 批次不区分单顶点与整段追加所需容量 | 使用 `count <= capacity && amount <= capacity - count` 判断，再写入 | 避免 `count + amount` 本身溢出，拒绝后已有数据不变 |
| 模板批次的步长、偏移与字节数固定按 `BlockVertex3D` 计算 | 全部使用实际模板参数 `T` 的大小 | 线框顶点不再按方块顶点步长读取 |
| 单顶点仅写 CPU，整段直接写 GPU，两种模式混用不一致 | 两种追加都进入同一 CPU 暂存；上传只处理有效元素 | `Draw()` 负责必要上传，已有 `ReloadData()` 调用可保留，脏标记避免重复上传 |
| 批次释放仅处理 CPU 内存，未删除 VAO/VBO | `Free()` 删除非零 VAO/VBO，并重置句柄、状态和暂存 | 支持部分初始化后清理与重复清理；调用时必须仍有当前 OpenGL 上下文 |

## 区块所有权与初始化

`Chunk` 默认构造时拥有完整的方块存储，初值为空气，顶点容器为空。裸邻居指针是非拥有关系：管理器负责节点生命周期，邻居指针不参与释放。

固定世界的初始化顺序应为：

1. 创建全部区块节点。
2. 建立完整邻居关系。
3. 按引用生成所有区块的地形。
4. 按引用生成所有区块的植被。
5. 生成需要更新的网格，再提交批次。

先完成全部地形再生成植被，避免跨边界植被写入尚未初始化的邻居，或随后被邻居地形初始化覆盖。上述调度位于应用层，由主实现统一接入。

地形初始化显式设置 `ToBeUpdated`；高度夹在合法区间内，石层高度不发生无符号下溢。噪声权重累计值在重新初始化时归零，噪声状态仅保留在实现文件中，不再由每个包含头文件的翻译单元生成一份。

植被保持原先由世界半径决定的候选范围，但额外限制在区块长宽内；边缘区块不自行生成植被。现有有限世界的边缘策略没有改造成无限世界。

`Chunk::Free()` 为显式清理接口，释放自身容器并清空自身邻居指针；它不负责修复其他区块指向该对象的指针。因此，正常整世界释放应使用 `ChunkManager::FreeAllChunks()`，而不是在仍被邻居引用时单独销毁某个区块。动态移除不在本阶段范围内。

## 顶点与批次契约

- `BlockVertex3D` 保持原字段布局。
- `LineVertex3D::pos_coord` 改为 `glm::vec3`，与渲染模块的浮点线框属性及微量膨胀一致。
- `DrawArraysIndirectCommand` 的四个字段改为 32 位，其结构大小为 16 字节；当前没有新增间接绘制路径。
- `Batch<T>` 禁止复制和移动，以免多个对象拥有同一组 GL 句柄。
- `SetBatchSize()` 只允许在没有已创建 GL 句柄时调用。容量必须为正，且顶点数和字节数都可由对应 OpenGL 参数类型表示。
- `Init()` 先清理旧资源，再创建缓冲和 VAO。对象创建失败或查询到的缓冲大小不符合申请大小时抛出异常。
- `AddVertex()` 要求初始化成功；空范围是无操作，非空范围的空指针会被拒绝。
- 超容量在任何写入前以 `std::length_error` 报告，不截断、不静默丢失区块，也不越界提交到 GPU。
- `ReloadData()` 仅上传当前有效顶点，不上传整个容量的未初始化区域。
- `Draw()` 在必要时上传，绘制后清空有效顶点，但保留 CPU 容器容量供后续帧使用。空批次不提交绘制。
- `Free()` 为幂等清理；析构也会调用它。应用层仍须在销毁 OpenGL 上下文前显式清理渲染器，不能依赖进程退出时的静态析构处理 GPU 对象。

默认 GPU 批次容量仍为 10,000,000 个顶点，本阶段不自动扩容 GPU 缓冲或拆分批次。容器安全不代表世界规模无限：超过该固定上限会得到受控异常，后续应由性能与世界规模设计决定分批或容量策略。

## 测试设计

### 区块与网格

`tests/mesh_safety_tests.cpp` 是不创建窗口、不需要 GL 上下文的单元测试，覆盖：

- 六向边界与组合越界、缺邻居读写和删除。
- 显式释放后的读写安全与重复释放。
- 跨区块边界写入及两侧网格失效标记。
- 空区块、单立方体 36 顶点、相邻两立方体 60 顶点。
- 224,028 顶点的隔离方块网格，明确跨越原 16 位上限。
- 重复生成不残留旧顶点，移动区块不共享或丢失所有权。
- 管理器重复创建、邻居重建、清空、重复清空与重新创建。

测试为方块格式查询和世界坐标转区块坐标提供窄范围替身，以隔离配置解析与世界实体初始化。它直接编译区块和管理器实现，不把配置加载或坐标转换替身的通过结果当作相应生产模块的验证。

### 批次与 GL 调用边界

`tests/batch_safety_tests.cpp` 给 GLAD 函数指针安装本地桩，不加载驱动、不创建 GL 上下文，覆盖：

- 容量判断的整数极值、恰好满与整段越界。
- 未初始化调用、零容量、不合法大容量与空指针输入。
- 单顶点与整段追加混用后数据顺序正确。
- 线框步长、GPU 存储与上传字节数按实际顶点类型计算。
- 只上传有效范围、重复上传抑制、空批次不绘制。
- 部分 VAO 创建失败、缓冲分配失败与重复清理。

这些桩验证调用参数和生命周期契约，但不验证真实驱动行为、视觉结果或性能。真实 GL 调试输出、重复启动退出及游戏视觉检查仍属于应用层验收。

## 后续不应混淆的工作

本次没有证明旧内存分配器、ECS 容器或整项目已经无泄漏，也没有完成性能验收。CPU 顶点暂存与每帧上传仍需后续基准测量；固定批次容量、透明材质排序、世界边缘显示和地形生成确定性也需要分别立项，不能由本次内存安全修改自动推导为已解决。
