# 类设计模板使用说明

默认使用 [轻量类设计](templates/03-轻量类设计.md)；有资源、复杂状态或回调风险时，按 [完整类设计](templates/04-完整类设计.md) 原地补充。示例：[[D3D12Lab-App-类示例]]。

仅描述组件、值类型、数据集合或视图契约时，优先使用 [数据与存储设计](templates/07-数据与存储设计.md)；描述系统函数、批处理或更新顺序时，优先使用 [系统与数据流设计](templates/08-系统与数据流设计.md)。真实资源所有者仍用类模板，不为模板增加不存在的类、继承或 System 基类。按维护需要拆分笔记，并互相引用，不要求每个模块建立全部类型。

主体是 namespace 函数集合的调用边界与静态状态时，使用 [namespace API设计](templates/09-namespace API设计.md)；CMake 目标与检查函数使用 [构建与依赖契约](templates/10-构建与依赖契约.md)，不要为两者虚构 class。

## 三段结构

| 区域 | 填写内容 |
| --- | --- |
| 当前设计 | 已实现的职责、成员、不变量、接口及生命周期 |
| 本次变更 | 本轮候选增量、关键操作及验收链接 |
| 后续考虑 | 触发条件 → 再考虑的变化 |

首次设计时，当前设计写“暂无”，将表格移到本次变更填写候选方案；验证后合并回来。轻量版只写必要增量，变化较多时采用完整版的增量表。无变化的章节不重写，不另建“类名-v2”。

## 继承关系字段

两份类模板均使用 `inheritance` 列表记录本类的直接基类；一项对应一个基类。C++ 写清继承访问方式，虚继承时加上 `virtual`。只记录直接继承关系，不重复展开祖先类；组合、成员和普通依赖不填入此字段。

无继承：

```yaml
inheritance: []
```

单继承，例如 `class D3D12App : public AppWin32`：

```yaml
inheritance:
  - "public AppWin32"
```

多继承（含虚继承的写法）：

```yaml
inheritance:
  - "public AppWin32"
  - "public virtual IFrameListener"
```

属性记录当前已实现的继承关系；首次设计尚未决定时可写 `inheritance: ["待定"]`。候选继承方案写在“本次变更”，实现并验证后更新此字段。继承理由、重写接口的行为约定，以及是否允许通过基类指针销毁对象，按需写在职责、接口或生命周期中；基类笔记用正文的 `[[基类名-类设计]]` 链接。

已有笔记可在 `class_name` 后手动补入该字段；修改模板不会自动更新已有笔记。

## 表格怎么维护

- **数据成员：** 类型、成员、初值 / 范围、含义与所有权。区分拥有、借用和值；缓存需写来源。同类型写法一致；按类型排序时整行一起移动，不能只排类型单元格。
- **不变量：** 一行一条可检查条件，写入实际成员名与成立边界。I1 等编号固定；接口、伪代码及验收引用编号，删除或排序后不重编号。
- **公开接口：** 独立六列表格，逐项写签名、调用方与可见范围、输出及状态变化、前提、失败反馈及失败后状态、源码与不变量。包含构造/析构及特殊成员；类 public 不自动等于模块公开 API。
- **私有函数：** 另设六列表格，写内部调用方、处理规则及副作用、前提、失败传播与清理责任、源码与不变量；private/protected 和内部 helper 注明范围。每个函数均有审核落点，不因实现简单省略；行为不同的 overload 分开。
- **不适用：** 没有相应函数时保留“不适用：原因”行，不创造方法。借用返回值注明有效期与失效条件，邻接对象函数链接其权威笔记；实现保证、调用者前提、目标与缺口分开记录。
- **生命周期：** 用短句说明持有者、借用失效、释放顺序、拷贝 / 移动及线程约束；有初始化失败或回调风险时再展开。

明显的生命周期、调用顺序、分支或清理流程优先用 Mermaid，再用短句补充前提、数值和失败后状态。表格回答“保证什么”，流程图回答“谁先调用、何时分支、谁收尾”；C++ 风格伪代码仅补充图难以表达的计算，不重复描述同一流程，也不把尚未实现的回滚画成保证。

## 验收与回写

优先链接功能笔记的验收章节，并注明对应不变量；没有关联功能或确需独立验证时，才保留类模板中的“状态｜场景｜预期行为”表格。两处不维护相同案例的结果。

实际通过后将 `[ ]` 改为 `[x]`，失败写 `[ ] 失败` 并记录原因。验证版本、运行入口和证据跟随唯一的验收记录保存；不能用推演代替运行结果。

完成时将增量合并进当前表格，保留简短取舍理由及证据链接，清空本次变更并更新 status。成员或接口改名时，检查不变量、伪代码和关联功能中的引用。

旧笔记迁移：已实现内容放当前设计，未落地内容放本次变更，未承诺能力放后续考虑；删除重复表格，并更新指向旧章节的链接。原始约定与证据应保留，不因精简丢失。
