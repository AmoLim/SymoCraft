# 构建契约设计

关联功能：[构建与测试边界](构建与测试边界.md)。本单元没有运行时 C++ 类，按实际构建契约记录 CMake 目标及检查函数；保留历史文件名，不用类属性或虚构构建管理器补覆盖。见 [对象清单的排除说明](../对象笔记覆盖清单.md#排除与验证说明)。

## 当前设计

职责是验证源码和目标的所有权、依赖方向及头可见性；各生产模块负责自己的实现，根构建不代管所有 `.cpp`。

### 数据成员

| 类型 | 成员 / 状态 | 初值 / 范围 | 含义与所有权 |
| --- | --- | --- | --- |
| CMake 选项 | `SYMOCRAFT_BUILD_GAME` / `SYMOCRAFT_BUILD_CPU_MODULES` / `SYMOCRAFT_BUILD_BENCHMARK` | 配置时确定 | 根构建拥有模块选择；CPU-only 局部覆盖，不写坏用户缓存 |
| 有向依赖表 | `SYMOCRAFT_ALLOWED_<module>` | 九模块的允许边集合 | 检查器拥有，仅表达允许方向，不自动链接依赖 |
| 第三方授权表 | `SYMOCRAFT_EXTERNAL_<module>` | 显式 target 名 | 防止 CPU 模块通过新增直接 link 获得图形 SDK |
| 目标属性 | `SOURCES` / `LINK_LIBRARIES` / `INTERFACE_LINK_LIBRARIES` / include 属性 | CMake 实际配置 | 检查读取实际属性，不维护第二份虚构生产图 |
| 构建期全局属性 | `SYMOCRAFT_SOURCE_<hash>` / `SYMOCRAFT_EDGES_<target>` | 当前 configure 生存期 | 实现唯一所有者和依赖遍历；不进入运行程序 |
| 输出文件 | `production-sources.tsv` / `production-dependencies.tsv` / `production-targets.dot` / `public-headers.tsv` | 构建目录 | 当前配置的证据，不覆盖冻结基准数据 |

依赖 TSV 保留 `raw_reference`，DOT 将静态库私有依赖标注为 `LINK_ONLY`。它表示最终链接仍需要该库，不表示其 include 使用要求公开给消费者；不能把 `INTERFACE_LINK_LIBRARIES` 中的此类条目误读为 PUBLIC 头依赖。

### 不变量

| 编号 | 条件 | 成立边界 |
| --- | --- | --- |
| B1 | 每个启用生产 `.cpp` 只有一个真实 owner，测试不得重编译它 | configure 成功时 |
| B2 | 模块实际 link 不越过允许依赖方向，生产不链接 test/app 反向服务 | configure 成功时 |
| B3 | 模块公开头不携带图形 SDK、YAML、噪声或私有存储头；私有桥接只有明确白名单 | source checker 成功且独立消费者构建成功时 |
| B4 | game/tool 生产不包含 test/support；关闭测试不创建辅助程序 | 所有产品配置 |
| B5 | target 图无环，外部执行器不链接游戏 | configure 成功时 |
| B6 | CPU-only 不创建窗口和图形库 | CPU-only 配置及实际 build.ninja 检查 |

### 接口与生命周期

两表覆盖 ThirdPartyHeaders、ModuleBoundaries、PublicHeaderTests、StageAssets 四个契约脚本的 8 个 function。CMake 没有 private 访问控制：公开指项目集成入口，私有指检查器 helper；测试直接调用的内部入口注明授权。第三方库的构建声明及环境/资源清单是脚本级配置，不伪装成额外运行时函数。

### 公开接口预期行为

| 签名 / 入口 | 调用方与可见范围 | 预期行为：输出及状态变化 | 前提 / 边界 | 失败反馈及失败后状态 | 源码 / 约束 |
| --- | --- | --- | --- | --- | --- |
| `symocraft_header_view(target, ARGN...)` | ThirdPartyGame/ThirdPartyYaml；configure 集成入口 | 在 binary/header-views/target 下 COPYONLY 指定 vendor header 集合，跳过 /src/，声明 INTERFACE target 及 SYSTEM INTERFACE 搜索根 | repository root/vendor 可读；target 尚未声明；目录 glob 仅 h/hpp/inl | 缺文件、拷贝或重名 target 等使配置失败；已复制文件不回滚，目标目录可能部分存在 | [定义][headers-cmake]；B3 |
| `symocraft_validate_boundaries()` | 根 CMakeLists 尾部及隔离负向探针；configure 集成入口 | 先扫源码、递归收集 targets；检查 owner/依赖/可见性/环与未拥有源码，成功后写 DOT 和两 TSV；保留 raw_reference | 启用产品/测试目标已声明；真实目标属性可读；当前 configure 单次汇总 | 检出违规 FATAL_ERROR；过程可能已写全局 SOURCE/EDGES/VISITED 属性，不做事务回滚；失败输出不当成完整清单 | [定义][boundaries-cmake]；B1-B5 |
| `symocraft_public_header_tests()` | test/CMakeLists 的 BUILD_TESTING 分支；configure/generate 入口 | 对已存在的九模块 targets 枚举公开 h/hpp；file(GENERATE) 写单头 cpp，建消费者 exe/CTest，链接正式模块；写 public-headers.tsv | caller 决定 BUILD_TESTING；函数自身没有该开关判断；仅生成模型，编译/执行发生在之后 | 目标或生成错误中止；模型/manifest 不自动回滚；缺失模块 target 直接跳过，生成成功不代表编译通过 | [定义][public-cmake]；B3/B4 |
| `symocraft_stage_assets(target)` | game/app 与 assets 测试目标；configure 集成入口 | 设置 target 的 runtime bin 路径，多配置附 CONFIG；添加共享 symocraft_runtime_assets 依赖，拷贝发生在 build | target 与共享资产目标已存在；以 PROJECT_BINARY_DIR 为基准，不用调用目录推断路径 | 配置期无目标等会失败；build 拷贝错误由构建工具反馈，不撤销已同步文件 | [定义][assets-cmake]；B4 |

### 私有函数预期行为

| 签名 / 入口 | 内部调用方 | 预期行为：处理规则及副作用 | 前提 / 边界 | 失败传播及清理责任 | 源码 / 约束 |
| --- | --- | --- | --- | --- | --- |
| `symocraft_check_source_file(root, module, source)` | check_source_tree；负向测试可直接调用的内部入口 | 读真实文件，提取 include，检查 owner 依赖、公开 SDK 暴露、相对跨 owner、私有头与宏 include；不改源文件 | root/module/source 有效，授权表可用；基于文本检查，不是完整预处理/AST 证明 | 违规具名 Boundary violation 后 FATAL_ERROR；读文件错误由 CMake 中止，不进行源文件恢复 | [定义][boundaries-cmake]；B2-B4；[授权探针](../../../../test/integration/CheckNegativeBoundaries.cmake) |
| `symocraft_check_source_tree(root)` | validate_boundaries；源码边界测试可直接调用的内部入口 | 按模块与 app/benchmark 扫 h/hpp/cpp，逐文件调用 check_source_file；检查源码不依赖 target 是否启用 | 仓库树与授权表可读；不扫 .disabled 为活动源码 | 首个读取/违规错误终止，未扫完部分不能称全部通过；无生产文件写入 | [定义][boundaries-cmake]；B2-B4；[授权测试](../../../../test/integration/CheckSourceBoundaries.cmake) |
| `symocraft_collect_targets(directory, output)` | validate_boundaries 及自身递归 | 读 BUILDSYSTEM_TARGETS/SUBDIRECTORIES，汇总子目录目标，set output PARENT_SCOPE | 目录已经参与当前 CMake 配置；不是全仓库文件扫描，不自动纳入 imported/alias targets | 不对非法目录自行提供错误值；CMake 属性错误会中止，返回的是当前构建模型 | [定义][boundaries-cmake]；B1/B5 的模型入口 |
| `symocraft_check_cycle(target, stack)` | validate_boundaries 及自身递归 | 当前 stack 已含 target 则报环；已 VISITED 则返回；沿全局 EDGES 递归，成功后设 VISITED=true | EDGES 已由收集阶段建立，stack 按递归值传递；一次 configure 检查模型 | 环触发 FATAL_ERROR；部分 target 可能已 visited，不自动清全局属性供修改模型后重复检测 | [定义][boundaries-cmake]；B5 |

### 阶段与失败边界

configure 时加载配置与 RequiredAssets 清单 → 第三方受限头 target → 模块/app/test 目标及部署依赖 → validate_boundaries → generate 单头消费者源码 → build 编译/资产同步 → CTest 执行。StageAssets 脚本加载时就检查必需资源，缺失则配置失败，不等到 stage_assets 函数或游戏运行。

这些接口只在 CMake 进程中运行，不持有 GPU、游戏对象或工作线程。重新 configure 重建目标模型；失败的负向探针使用独立构建目录，不污染正式缓存。生成消费者内容未变时不更新时间戳，避免每次配置都触发无关重编译。

### 白盒授权

| 消费者 | 授权 | 理由 |
| --- | --- | --- |
| world 网格/生成/契约/分配/成本测试 | world/src | 私有窄适配器读取正式 owner 状态；不新增公开注入 API，不重编译生产实现；原 robin_hood 授权随旧容器移除 |
| `shader_loading_tests` / `batch_safety_tests` | renderer/src + GLAD；后者另链接 world | 真实实现上替换现有 GLAD 函数指针，不创建影子 shader 库；World→Batch 空发布组合不是 GPU 运行证明 |
| `gpu_timer_tests` | renderer 公开头 + GLAD | 只替换底层 query 函数，公开计时接口保持 SDK 中立 |
| `startup_options_tests` | app/src | 私有启动契约，不向模块公开 Application |
| `benchmark_runner_tests` | tools/benchmark/src | 独立工具内部进程协议测试，不获得游戏路径 |
| `key_snapshot_tests` | platform/include，不链接 platform | 纯输入值类型可在 CPU-only 配置验证 |

### 既有 T0 实现与验收

M3-T0 构建契约已实现并通过最终 Debug/Release、CPU-only、隔离构建和增量头检查，结果已并入[关联功能验收表](构建与测试边界.md#验收案例)。无待实施增量。旧编译告警不等于本轮已修复其底层 ECS/内存风险，后续 T5 仍需专门审计。

## 本次变更

T1 更新实际 world/simulation target 和 world 第三方允许表；未扩大游戏对测试或图形私有路径的授权。源码唯一 owner、公开头及负向检查、产品矩阵和故障扫描配置边界，归 [T1报告](../../../milestones/m3-t1/README.md#构建与故障扫描)。以上 T0 验收仍是历史快照。
