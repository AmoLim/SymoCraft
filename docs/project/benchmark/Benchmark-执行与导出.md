# Benchmark 执行与导出

关联类 / 协作者：[[Benchmark-App类]]、[[Benchmark-Process类]]、[[Performance-Session类]]、[[Benchmark-文件协议]]、[[CMake-模块边界]]。

## 当前设计

`tools/benchmark` 是独立的 Windows x64 C++20 工具。GUI 负责选择、展示和取消；核心 `Run` 负责固定计划和数据有效性；`Process` 负责本进程创建的子进程生命期。游戏拥有世界、GL 上下文、GPU 查询和测量，执行器没有引擎内部对象访问权。

```text
GUI/CLI 配置 → Run(配置副本, stop_token, 观察回调)
 → SHA256 身份、机器环境、新会话目录、排他锁
 → 新 attempt → Process → 游戏 CLI
 → status.yaml → 只读进度
 → 退出码 + summary/CSV → 校验 → result.yaml + session.yaml
 → 成功：下一轮；失败/取消：停止、保留现场
 → Export → 白名单复制/已知路径替换 → SHA256 清单 → 系统 tar → results.zip
```

关键约束与理由：

- 不依赖脚本执行策略。进程创建、日志、哈希、环境采集都是 Windows 原生 API；ZIP 用系统 libarchive/tar，不自研压缩格式。
- 不链接 GL、GLFW、引擎对象；只复用仓库已有 yaml-cpp 这个第三方解析器。测试夹具也不链接游戏。
- 默认 36 分钟，另有 60 秒快速检查。初始化/验证/截图耗时额外计算；不自动缩短用户确认的协议。
- 环境采集读取 CPU 名、物理内存、Windows build、AC 状态、电源计划 GUID；GPU/驱动以游戏当前 GL 上下文为准。手填声明另列，不自动推断超频/降压/混合模式。
- NVIDIA / AMD / Intel 不作为通过条件；温度不采集，NVX 显存可缺失。不为采样安装驱动或切换系统设置。
- 新运行要求全新目录；重试同一配置/同一包，重新验证已通过轮次，从首个失败轮次新建 attempt，再做剩余轮次。重试后的组合与连续基线明确区分。
- 目录写失败等外层异常会交给 GUI/CLI 报错；已有文件保留，不承诺磁盘故障时仍能写出最终报告。运行中的游戏由 Job 自动收尾。
- 导出保留本地原始记录；只在新导出副本替换已知路径。文件白名单和非 reparse 路径检查避免意外收集整个项目。无网络上传功能。

### 验收案例

| 状态 | 场景 | 预期行为 |
| --- | --- | --- |
| [x] | 固定协议和 SHA256 标准向量 | 正式 2160 秒、9 轮；快速 60 秒、3 轮；正确哈希 |
| [x] | 中文/空格/引号/末尾反斜杠/`&` | 参数原样到子进程，不经 shell |
| [x] | 原生夹具：Intel/AMD 设备字符串、可选显存缺失 | 与 NVIDIA 无关，不凭品牌拒绝 |

| [x] | GUI 交互、轮次间取消后继续、导出、中文便携目录 | 短测与导出成功，桌面布局无重叠；不是实机轮次内取消测试 |

| [ ] | Y9000P、无开发环境机器、AMD/Intel 真实驱动 | 各自实机验收，不以夹具替代 |

环境 / 入口：Windows x64，MSVC 19.38；`ctest --test-dir out/build/benchmark-debug --output-on-failure`，Release 对应 `benchmark-release`。夹具用例位于 `tools/benchmark/tests`；游戏已有 17 项回归继续保留。

验证版本 / 证据：本次未提交工作树，最终 Debug/Release 各 20/20，三种隔离构建通过。详见 [[Benchmark-桌面交付验证]] 和 `evidence/build-identity.json`。真实 GUI/GPU 短测早于最后的界面细节与元数据措辞修订，报告区分两个二进制身份；不能把短测作为最终包的完整实机回归或正式性能基线。

实现落点：`tools/benchmark/src/main.cpp`、`gui.cpp`、`runner.cpp`、`platform.cpp`。

## 本次变更

无。已验证的原生执行、重试、导出及有限桌面测试结论合并至当前设计。状态“已验证”限上表已勾选范围，不代表 M2 整体通过；未执行项保留，不自动启动 36 分钟正式采样。

## 后续考虑

| 触发条件 | 再考虑的变化 |
| --- | --- |
| 多人回收需要统一查看 | 增加独立离线结果分析工具，不让执行器变为引擎模块 |
| 跨厂商温度/显存成为验收必须项 | 单独设计可选采集后端，注明来源、权限和成本 |
| 需要自动恢复被中断的 GUI 会话 | 增加显式导入入口；当前重试留在本次 GUI 会话，CLI 可显式 resume |
