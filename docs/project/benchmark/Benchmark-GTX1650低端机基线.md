# Benchmark GTX 1650 低端机基线

本次归档 Yecat 于 2026-10-04 完成的修复版 1080p 三场景九轮结果。**9/9 采样有效，旧尺寸故障未复现；不代表稳定 60 FPS 达标。** 2026-10-05 用户确认将该 i7-10750H / GTX 1650 整机指定为低端性能基准，将 Y9000P 指定为中端性能基准，唯一的设备与目标定义见 [项目范围](../../spec/project-scope.md)。

## 要回答的问题

- 修复包能否在原失败机器完成真实 1920×1080 的完整采样？
- 指定低端机当前帧时、长帧和数据提交成本是什么？
- 关联功能：[[Benchmark-1080p窗口修复]]、[[Benchmark-执行与导出]]、[[Performance-失焦采样]]。

## 假设与判据

- 数据有效：同一包及资源，static / walk / edit 各三轮，每轮预热 60 秒、采样 180 秒，实际 framebuffer 为 1920×1080，正常退出且原始数据与摘要一致。
- 性能与有效性分开：中端原有 P95 ≤16.7 ms、P99 ≤33.3 ms 仅用作本次观察参考；低端硬性性能目标待单独确认，不把分级变更当成达标结论。
- 允许失焦，不最小化；约 99.90% 正式采样时间实际失焦，定位为日常使用基线，不能当作受控前台体验或输入到显示延迟测量。

## 实验步骤

1. 测试方使用窗口修复包执行九轮，收到的会话显示无重试、取消、超时或强制结束，`continuous_full_protocol=true`；不据此补写未收到的快速检查结果。
2. 回收包已有离线分析报告，记录逐帧复算、时长/焦点/编辑计数检查及长帧定位；完整原报告随原始材料保留，不修改其历史口径。
3. 本次归档重新核验附带清单 82/82 文件哈希，检查会话及九轮摘要，抽查 edit 3 长帧和下一帧补做记录；未重跑游戏，不冒称本轮重新完成全部逐帧复算。
4. 原回传目录保持不变，完整复制到独立本地归档目录；84/84 文件与来源逐字节哈希一致。向 docs 精选复制 57 个原始文件并逐项核验，另生成归档索引。

## 结果记录

### 完整性与帧时

九轮退出码均为 0、摘要有效，实际 framebuffer 均为 1920×1080；该机器旧版 1920×1061 的启动失败在本次未复现。正式样本共 101,672 帧，GPU 查询缺失 9 帧，不补零。估计失焦 1,618.319 秒；失焦比例不等于遮挡面积。

| 场景 / 轮次 | 吞吐 FPS | P95 ms | P99 ms | 最大帧 ms |
| --- | ---: | ---: | ---: | ---: |
| static 1 | 60.65 | 20.8622 | 24.5137 | 38.7236 |
| static 2 | 60.64 | 21.2824 | 24.4782 | 33.1026 |
| static 3 | 60.45 | 20.8465 | 23.6701 | 41.1302 |
| walk 1 | 60.38 | 21.9125 | 25.1621 | 37.7793 |
| walk 2 | 60.64 | 21.2058 | 24.7828 | 47.1006 |
| walk 3 | 60.67 | 21.5394 | 24.6432 | 33.6946 |
| edit 1 | 59.68 | 21.2884 | 24.3887 | 30.7363 |
| edit 2 | 69.75 | 17.4782 | 21.5254 | 273.9597 |
| edit 3 | 71.98 | 16.2124 | 19.0554 | 439.8147 |

static / walk / edit 的三轮 FPS 中位数分别为 **60.64 / 60.64 / 69.75**，P95 中位数为 **20.8622 / 21.5394 / 17.4782 ms**；这是逐轮指标中位数，不是合并帧分布。8/9 轮 P95 高于中端参考线，9/9 轮 P99 低于 33.3 ms。原离线分析记录 35,788 帧超过 16.7 ms、10 帧超过 33.3 ms、2 帧超过 100 ms。

### 长帧与成本

| 轮次 / frame | elapsed_s（含预热） | 总帧时 ms | 主要异常区间 | 同帧编辑 / 重建 |
| --- | ---: | ---: | --- | --- |
| edit 2 / 5677 | 95.5615762 | 273.9597 | present CPU 259.3070 ms | 0 / 0 |
| edit 3 / 16880 | 231.9791095 | 439.8147 | upload CPU 432.8755 ms | 0 / 0 |

两帧均失焦，但没有同时发生焦点转换，不能直接归因于 Alt+Tab 或编辑重建。edit 3 下一帧补做 2 次写入，最大迟到 418.9242 ms；本轮仍完成 720 次写入，重建 2,157 次，前两轮各为 2,160 次。同帧写入合并脏区块更新可减少重建次数，不能据此认定漏编辑。

edit 三轮 FPS 从 59.68 到 71.98，最大/最小差约 20.62%；原分析的每 60 秒分段显示 edit 2 后半程持续变快，不只是两帧异常。后台活动、频率、电源和调度变化均缺少同步证据，根因未定，不只取较快轮次代表成绩。

static / walk 没有编辑或重建，仍每帧整理并上传约 **55.09 MiB**。两场景 pack 平均耗时的三轮中位数约 8.53 / 8.57 ms，upload 约 7.84 / 7.82 ms，GPU draw 约 0.67 / 0.56 ms。优先调查重复整理、全量上传及驱动等待；CPU 墙钟区间不是纯计算成本，GPU draw 不覆盖上传、clear 和 swap。pack 已包含在现有 submit 不含 upload 指标中，不重复相加。

含预热的约 1 秒间隔内存记录中，工作集最高 551.20 MiB、private bytes 最高 1,191.42 MiB。九个独立短进程不能证明长期无泄漏。[最终截图](evidence/yecat-gtx1650-20261004/static-1-attempt-1/capture/final-frame.png) 为采样后额外渲染，不代表整段可见性或玩法验收。

## 结论

- **采样与尺寸复测通过所覆盖范围**：本次九轮完整有效，原机尺寸失败未复现；不追溯改写旧失败结果。
- **指定低端机基线已归档**：用户确认设备角色；允许失焦的数据继续作为日常使用对照，不升级为受控前台性能或最低配置认证。
- **性能风险保留**：8/9 轮 P95 高于中端参考线，存在两次明显停顿和轮次漂移；低端硬性目标仍待确认，M2/M4 不因此通过。
- 中端 Y9000P 仍需自己的有效基线。低端机的受控复测、温度/频率和异常诊断另行安排，不自动启动采样。
