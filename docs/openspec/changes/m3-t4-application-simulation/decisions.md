### D09 演进触发

仅当真实生产工作负载的结果构建/增长/交接出现持续可复现分配/复制成本并影响已确认预算，或负载实质扩大导致明确容量复用要求无法满足，才定位并比较方案2。不是多实体/按值返回就触发，不预设数量/耗时/分配阈值，不自动授权。
采用前须用户审核/基准对照，仍由caller拥有、旧结果保留/显式覆盖清楚；明确别名/容量/覆盖/失败状态，保D04与同序列行为，不换内部借用/静态缓冲或长期两实现。当前实现处留理由/所有权/触发注释，落实后architecture更新实际机制，不先写目标为现状。

## 未决接口

Q01-Q04仅细化原契约未冻结表面，不重开D01-D13；**四项均未选择**。推荐不是批准。

### Q01 实体装配入口

1. 中立生产helper创建角色，Session只绑定有效EntityId：入口直接，但caller与会话需核对同一组件前提。
2. Session工厂在caller已注册组件的专属Registry/World及初态中创建玩家（原推荐）：装配归属集中，仍依赖caller注册和专属范围。
3. simulation工厂在专属空Registry注册组件并建玩家：前提集中，增加注册责任与空Registry限制。

共同底线：World/Registry借用寿命覆盖会话；失败不发布并销毁专属范围，不保证任意共享Registry事务；析构不清借用存储，无Camera实体/Engine/GameSession/safeSpawn语义扩张。

### Q02 原始键盘事实

1. held/pressed分开并保Down合并便利入口（原推荐）：事实可区分、消费直观，公开字段增加。
2. 合并Down加真实held和本窗口queued Escape事实：对旧消费者改动小，退出锁存有独立特例。
3. 有序键盘事件加held，app reducer维持sticky：表达最完整，但迁移/顺序状态责任更大。

共同底线：短按一次、held重采、鼠标held非sticky、局部Escape跨失焦、同轮失焦获焦、Wait首事件全部保持，不补后台全局Escape；平台发布事实不执行玩法策略。

### Q03 关闭报告交接

1. 返回自有ShutdownReport聚合步骤状态/首因（原推荐）：所有结果可直接汇FinalFacts，但增加显式结果检查。
2. 失败抛app私有ShutdownError并自有完整report：贴近现异常出口，成功/失败交接需分支。
3. 抛首错并由owner保LastShutdownReport只读：调用方须读取同owner报告并维持其寿命。

共同底线：清理全部适用步骤、首因主/次错分开、重复Shutdown同事实不重试资源，不改变D3D12 quarantine；未取得不等于已安全关闭、未知不填安全；析构有界且不Seal/Export，OOM允许有限诊断。

### Q04 只读诊断可见范围

1. 公开窄Inspect返回自有SessionDiagnostics（状态/余数/冷却/必要运动，原推荐）：CPU消费者直接验证，增加public契约维护。
2. test friend只读自有capture：公开面最小，但测试与私有布局耦合。
3. 模块私有统一adapter加授权根test include：有独立采集边界，需明确私有访问授权与构建隔离。

共同底线：不推进/改预算/状态，Ready/Paused/Rejected/Failed已知事实可核查、未知显式不填0；不暴露组件地址/可写状态/整个World/ECS快照，D12字段/阈值不变。
