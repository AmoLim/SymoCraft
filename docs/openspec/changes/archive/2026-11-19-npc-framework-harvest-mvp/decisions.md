## 后续选型

2026-11-09，用户确认 Q01-A 与 Q02-A。两项选择沿用 S1 与 F1。下列开销是结构性估计，实际成本随候选测量。

### NPC-MVP-Q01 方块目标身份

| 候选 | 机制与取舍 |
| --- | --- |
| **Q01-A · 稀疏单格版本（已选）** | NPC 场景启用 World 私有表，只记录实际变更过的坐标。未变更格读初始版本，首次改变先准备表项，再与方块和已有版本一起提交。获取标识是纯读，内存随不同编辑坐标数增长，首次编辑可能分配。 |
| **Q01-B · 每格固定版本** | World 初始化时为每格预分配版本，编辑路径直接定位。访问与内存量可预测。默认 441 区块若每格加一个 64 位版本，约增加 220.5 MiB，未计容器开销。 |
| **Q01-C · 只跟踪活动目标** | 只为当前动作关注的格维护可失效标识，多个 NPC 可同时关注同一格。内存随活动目标数量增长。需要在有写权限的边界登记和释放，`Advance` 只产生待登记意图，登记完成后动作才持有目标，取消和退出路径更多。 |

三案都必须识别同种方块拆除后放回。World 的区块 content revision 粒度过粗，同一区块的其他格编辑会误伤有效目标。无变化编辑也应保持目标有效。见 [World 增量](specs/world/spec.md#requirement-conditional-removal-of-a-harvest-target)。

### NPC-MVP-Q02 采集计时

| 候选 | 机制与取舍 |
| --- | --- |
| **Q02-A · 会话有效规则时间（已选）** | 对已处于采集阶段的动作累加 `Advance` 校验、裁剪后的规则时间，与现有角色冷却用同一时间口径。恢复首帧为零，正时间但零物理步的调用仍可累计。接线最少，完成在调用边界判定。 |
| **Q02-B · 已完成物理子步** | 采集期间按实际完成的 120 Hz 子步计时，零物理步不累计。长帧受最多八步限制，可能比规则时间累计更少。若需精确区分移动与采集的切换步，须提供相应的子步阶段信息。 |
| **Q02-C · 独立固定动作步** | 用会话有效规则时间驱动有界的 NPC 动作累计器，固定间隔结算进度。可单独调节动作频率，需新增余数、追赶上限及超限口径，并承担离散化误差。共用原物理预算。 |

动作从合法到达后的有效采集阶段开始计时；暂停和恢复、旧目标失效及同帧提交顺序按既定规格。按 A 使用会话返回的有效时间核对长帧、零物理步和恢复首帧。见 [采集增量](specs/npc-entities/spec.md#requirement-timed-harvest-action)。
