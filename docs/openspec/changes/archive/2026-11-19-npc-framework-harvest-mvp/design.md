# NPC 框架与耗时采集 MVP 设计

## Context

目标范围见 [proposal](proposal.md#capabilities)，可观察行为以各增量规格为准。本设计按已确认的 [S1 与 F1](decisions.md#已确认)以及 [Q01-A 与 Q02-A](decisions.md#后续选型)组织接口和提交边界。

现有 `SimulationSession` 串行借用专属 Registry 与只读 World，Application 负责编辑提交、网格及画面编排；此前候选已接入 NPC 串行采集和整体静态角色显示。角色导出仍合并身体，导入烘焙节点变换，显示交接仅含整体位姿，尚无本次所需的分件动作和演示控制。2026-11-16 的目标扩展以 [角色导入](specs/character-assets/spec.md)、[动作显示](specs/renderer/spec.md)和[演示控制](specs/application-lifecycle/spec.md)为准；历史验证保持原候选范围。见 [会话](../../../../../game/modules/simulation/include/symocraft/simulation/session.h)、[应用循环](../../../../../game/app/src/application.cpp)、[World 编辑](../../../../../game/modules/world/src/world.cpp)和[渲染输入](../../../../../game/modules/renderer/include/symocraft/renderer/types.h)。

## Technical Approach

### N1/N2/N3 交接

下表类型名描述语义和最小字段，具体 C++ 命名随实现核对。

| 交接 | 值和职责 | 所有权与失效 |
| --- | --- | --- |
| N2 → N1 动作意图 | 实体身份、请求的动作、目标坐标或工作点参数。N1 完成校验并签发动作标识。N2 可按标识轮询、取消。 | N1 按 `EntityId` 与动作标识成对核对。结束、切换或实体移除使旧标识失去提交资格。N2 只持有值，校验和写入都经 N1。 |
| N1 → N2 动作状态 | 动作标识、阶段、进度、成功或失败原因。状态最少区分移动、采集、就绪和终态。 | 就绪表示达到耗时，成功只来自提交终态。N2 对终态消费一次。已保存的结果值不随下次推进改变。 |
| N1 → 提交入口 | 会话和本次推进的标识、自有玩家编辑请求，以及 NPC 就绪记录。就绪记录含实体、动作、固定顺序键和 World 目标标识。 | 一次性提交数据只在当前会话和推进有效。调用方负责在下一次推进前提交，或在取消、关闭边界显式作废。 |
| N1 → N3 显示事实 | 本轮身份、实体身份、角色模型键、世界位置/朝向、实际位移、动作标识/阶段、有效已耗时/总耗时，以及已提交结果和资源计数。 | 在推进及提交完成后提取自有中立值，不持有 ECS/树指针。应用生成分件姿态和演示反馈，Renderer 只消费自身资源句柄及绘制值；显示不成为动作或库存的第二权威。 |

游戏路径与无窗口路径共享 N1 的推进和提交入口。N2 可先用动作替身核对树与端口绑定，N3 可先用代表性显示值核对导入与双后端。N1 负责接入 Application 的帧编排，真实采集证据来自正式 World、物理和动作实现。

### N1 实体、移动与进度

- **装配。** 复用专属 Registry 和 typed ECS。门面持有非拥有 `EntityId`，组件保存位姿、移动和玩法数据。会话装配显式注册共享与专属组件，预检出生位姿和顺序键，完成组件和运行状态准备后才纳入活动集合。装配失败保留既有活动实体，启动失败沿用专属装配范围丢弃规则。查询中只收集自有值，退出全部查询后再增删组件或实体。移除先完成可失败的预检，成功后注销动作和树状态，显示交接不再包含该身份。
- **移动。** 首批平坦场景按目标四个水平相邻格确定工作点候选，检查地形支撑、角色 AABB 空间与工作距离，按距离与坐标稳定裁决。驱动现有刚体进入到达容差，位置取物理实际结果。场景配置给出有限正的速度、工作距离、到达容差和受阻时限。实际物理步持续未取得有效进展时结束为受阻，零步与暂停不消耗受阻时限。抵达并核对仍处于有效工作位置后进入采集，随后失去有效工作位置按动作中断处理。僵尸 Idle 保持零移动意图。
- **进度。** 接受目标时绑定原方块身份及已校验的规则值，开始采集时记录有效耗时。按 Q02-A，仅本次推进开始前已处于合法采集阶段的动作消费 `AdvanceStatistics::rule_seconds` 对应的有效规则时间。本次抵达从下次推进起计时；仍在合法工作位置且目标有效时，正时间的零物理步也累计。恢复首帧规则时间为零。累计值达到门槛后饱和为就绪，等候本次提交。取消、任务切换和目标失效使动作终结；暂停保留进度。
- **World。** 采集规则随现有方块定义一起校验发布，可选字段缺失仍兼容当前方块定义。按 Q01-A，NPC 场景在 World 装配时启用稀疏单格版本表，存续期间保持该设置。目标标识包含 World 身份、坐标和该格版本，未记录格读初始版本，查询无写入。所有受控编辑共享预检与提交路径。语义无变化和其他格编辑保留原目标。同坐标发生实际变化时，先校验单格及现有区块版本耗尽并准备缺失表项，再无失败地发布内容及各版本。表项保留至 World 销毁，同坐标版本不回绕或复用。条件移除在同一编辑边界重新核验目标标识。

### N1 提交与 F1 失败边界

NPC 场景的推进结果可交接一个自有、一次性的帧编辑批次。建议由 `SimulationSession` 提供一个提交入口，接收当前批次及调用方提供的可写 World。入口核对同一会话、World 身份和推进代次，已提交、作废、跨会话或跨世界的批次在写入前拒绝。`Advance` 继续只读 World。既有无 NPC 调用方继续使用原玩家请求路径；NPC 场景的应用与无窗口验证统一走该入口。

1. **提交前准备。** 冻结当前批次，检查顺序键并准备结果槽。普通玩家编辑继续走现有 `TryEdit` 和冷却规则。已有性能场景的模拟前编辑保持其原路径。准备批次遇不可恢复故障时按当前阶段结束会话。
2. **S1 排序与复核。** 玩家编辑有结果后，按场景键升序逐个处理 NPC。每次重新确认实体有效、动作仍就绪、工作位置和原方块标识仍有效。场景键与 `PhysicsStepOrder` 各自表达不同业务顺序，可以来自同一份装配配置。失败或完成后停止推进该动作，下一候选按当前世界复核。
3. **F1 准备。** 在目标移除前算出校验后的资源新值，准备该 NPC 的写入和终态。建议资源计数采用按资源 ID 排列的拥有值容器。更新已有计数预先校验加法；增加新资源项时先构造候选容器，再以同分配器的无异常交换发布。结果写入预先准备的结果槽。准备失败时丢弃候选值；当存储一致时登记失败并继续后续候选。
4. **F1 提交。** 在同一个串行、非重入调用内，World 条件移除再次确认原目标。仅在 `Changed` 后更新计数并发布成功终态。此段只执行已准备的值写入或交换，避开分配、回调、日志格式化、树 tick 和 ECS 结构修改。World 拒绝、无变化或准备故障时放弃候选计数。已成功修改 World 后若内部约束仍被打破，将会话置为 Failed，再向应用交接已知阶段、目标和提交事实。未知信息保持未知，保留已有提交。Application 停止新推进和帧提交，沿现有错误路径清理。
5. **发布。** 读诊断和提取显示值发生在提交边界之外。Application 随后处理 World 网格、角色实例绑定和帧提交。网格或 GPU 故障沿各自路径报告，已经完成的玩法结果仍由 N1 和 World 持有。

在第 3、4 步内可以短期借用待更新组件，前提是该区域没有 Registry 结构操作、重入或用户回调。构建结果和记录诊断所需的分配放在临界段之外，故障摘要可以只带预留的数值与枚举。验证从真实 World 的方块和版本、动作终态与资源计数读取结果，注入准备失败和约束破坏时分别确认触达阶段。见 [A23](specs/application-lifecycle/spec.md#scenario-npc-mvp-a23-player-and-npc-attempt-to-remove-the-same-block)、[A24–A25](specs/simulation/spec.md#scenario-npc-mvp-a24-stable-order-for-simultaneous-contenders)和 [A26–A29](specs/npc-entities/spec.md#scenario-npc-mvp-a26-credit-preparation-failure-preserves-the-target)。

### N2 树资产与动作适配

- **运行所有权。** simulation 的私有 AI 适配拥有节点注册、经校验的树定义与每个实体独立的树实例和黑板。节点注册表同时提供项目节点模型导出。场景在发布前校验各树入口、子树引用与循环、节点和参数类型，表达式仅允许规格列出的运算与黑板赋值。校验应覆盖实际可执行的表达式入口，运行层只注册本 MVP 支持的组合与动作节点。黑板使用受控的值类型，玩法资源通过动作状态或诊断快照读取。[BehaviorTree.CPP 表达式说明](https://behaviortree.dev/docs/guides/scripting/)
- **节点时序。** 每次正有效时间的 `Advance` 对活跃 NPC 各提供至多一次有界树更新机会。先从上次已完成的提交读取结果，再收集本轮意图，之后由 N1 驱动物理及采集。动作节点初次启动得到动作标识，轮询同一标识时在移动、采集和就绪阶段保持运行，终态由 N1 决定成功或失败。树节点被中断时发出取消请求，当前动作终结后才接替代动作。N1 的动作处理可独立运行。场景树须能在根节点再次更新时继续保持 Idle，僵尸只运行独立的 Idle 树。
- **预算与诊断。** 启动时限定树大小、深度和每次更新可触及的工作量。选择有界节点组合，避免一次更新内部因循环、等待或外部回调占住会话。以 2 名人类与 1 名僵尸建立配置和实测依据，具体上限随候选资产校验。日志从状态变化生成，按需快照复制已经安全取得的字段。实体移除先预检并撤销动作资格，再释放对应运行实例。正常关闭在 Registry 与 World 仍有效时结束树和动作；Failed 清理只释放自有状态与已取得资源，节点的停止与析构路径不得回读不可靠的存储。
- **部署。** BehaviorTree.CPP 作为 simulation 的私有编译依赖，固定来源、完整版本与许可，先核验 MSVC/DBG01、CPU-only、普通构建与必要功能选项。Groot2 FREE 是离线资产编辑入口，树资产和运行所需文件随游戏部署，编辑器与运行时分开。[Groot2 官方说明](https://www.behaviortree.dev/groot/)

### N3 导入、角色实例和帧准备

- **CPU 导入。** 由现有 `assets` 持有 cgltf 私有实现，输入为经现有资产路径解析得到的 GLB，输出自有角色顶点数据。首版接受能表达两份交付模型的自包含静态三角形数据，使用位置、法线及顶点色。读取前核对文件范围、缓冲和 accessor 的偏移、计数、步长、索引与乘加溢出；拒绝必需外部资源、未支持的压缩或稀疏表示、不可解释的 primitive 和非有限数据。用 cgltf 解析和校验，另做项目输入和输出边界校验；只在全部 primitive 转换后发布。暂定展开成非索引三角形，避免为验证模型增加一套索引绘制路径。保留 Blender 源和实际导出的 GLB，正式部署清单仅包含游戏消费的资源。[cgltf 上游接口](https://github.com/jkuhlmann/cgltf) · [glTF 2.0 规格](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)
- **坐标与颜色。** 约定模型原点在脚底，GLB 的 Y-up 和 +Z 前向统一由应用映射到实体朝向，单位在导出规约固定为一米对应一个基础方块边长。整体静态输入继续兼容原烘焙路径；分件输入保留局部绑定变换与父子关系，网格转换校正法线和绕序，拒绝不可解释或不可逆的变换。顶点色按线性 RGB 输入，两后端用同一简单光照和不透明绘制规则。实体世界位姿仅在实例变换时应用。
- **分件资产。** 修改 Blender 制作/导出流程，保留躯干、头、左右臂和左右腿的稳定名称及局部坐标，在肩和髋显式定义旋转轴；脸和头发随头部刚性附属。使用现有 cgltf 路径输出自有分件几何、绑定变换及关节轴，不以运行时顶点位置分类或包围盒中心猜关节。发布前校验必需部件、名称唯一、父子无环、有限变换及关节数据，并对部件数和几何规模设上限。两份验证模型保留可编辑源，静态兼容输入不要求补造可动元数据。
- **显示交接。** `GameRenderer` 按模型键持有共享 CPU/GPU 分件网格映射，并按 N1 的活动实体值构建当前帧实例列表。复用角色绘制的逐对象变换，组合实体根变换、部件绑定变换和绕轴旋转；姿态只更新绘制值，不逐帧变形或重传网格，不增加蒙皮着色或动画库。各 NPC 的姿态独立，共享不可变网格。同一 Renderer 在现有帧准备时一并校验方块和角色绘制，D3D12/Vulkan 消费同一中立输入。角色使用同一帧相机、深度和呈现边界。实体移除后不再产生该实例绘制；其他实例或已提交帧仍使用的模型保留到引用结束及后端完成。释放与显式关闭沿用现代 Renderer 生命周期，窗口覆盖其寿命。
- **程序动作。** 姿态缓存按本轮、EntityId 和动作标识隔离。行走相位由实际水平位移累计，受阻且无实际位移时不原地走路；采集摆臂仅在真实采集阶段按有效已耗时计算，到达、就绪及终态不虚增采集时间。暂停保留当前姿态，退出对应动作后回到中立姿态；不要求复杂混合、肘膝弯曲或 IK。未知动作数据不能伪装为正在采集，失败/取消/实体移除清除相应缓存。可观察结果见 [A34–A35](specs/renderer/spec.md#requirement-state-driven-rigid-character-motion)。
- **验证。** CPU 导入测试核对 Blender 实物导出、坏文件诊断、方向和属性，不依赖 GPU。正式候选分别核对 D3D12/Vulkan 画面、共享资源与在途销毁，GL 只执行受影响回归。默认场景和人工时限沿 [应用增量规格](specs/application-lifecycle/spec.md#requirement-npc-mvp-assembly-and-bounded-evidence)。

### 应用演示控制与反馈

本节实现 [A36–A38](specs/application-lifecycle/spec.md#requirement-observable-harvest-demo-controls)。Application 持有独立的演示控制状态：Ready、Playing、Paused、Completed。Ready 展示初始场景并等待开始，Playing 才允许树、模拟和采集提交；全体人类终结并进入 Idle 后显示 Completed，允许从头重新演示。Paused 冻结模拟及姿态但继续绘制可用窗口和控制。普通失焦/最小化仍遵守现有平台策略，手动暂停标志不会因重新获焦自动清除。通过会话 Pause/Resume 清除旧输入和时间债，恢复首帧规则时间为零；暂停时不以调用 `Advance(0)` 代替停止推进。

每轮由应用拥有可替换的运行上下文，集中拥有 World、Registry、Session、树和场景实体。默认单人场景展示完整一次采集；争抢对照复用原规则和稳定顺序键，僵尸布置在侧边。保留两人独立目标的三 NPC 正确性夹具，不将其删除或变成默认单人场景的计数断言。演示用清晰的观察视角及布局，不添加演示内拆放干预；普通玩法和独立性能场景保持原路径。

开始、暂停/继续、从头重新演示和场景选择须有画面内可发现的入口或按键说明。从头重新演示和切换场景均在串行帧安全边界执行：先完成当前已开始的提交或按既有规则作废未提交批次，停止旧树及动作，释放旧会话，再释放其借用的 Registry/World；移除旧 WorldId 的渲染缓存，清除本轮姿态、进度和结果，再创建具有新身份的初态。不能跨替换保存 `world` 等长借用，旧批次不能进入新轮。窗口和 Renderer 可复用，但帧号及 GPU 完成序列不重置，在途资源仍按后端完成规则退休。装配失败报告错误并停止该演示，不冒充恢复成功。启动时已校验的不可变资产可复用，此操作不提供运行中树资产重载。

演示反馈由提交后的只读值生成，按本轮和实体身份关联名称、当前阶段、目标、采集进度、资源计数及终态原因。采集进度仅在有效耗时已知且为正时计算，显示范围限定为 0–100%；就绪可显示等待提交，不等于成功。只有真实 World 移除且资源入账后显示成功；争抢败方展示目标失效及未获得产出，未知结果保留未知。切换和重播清除旧提示，重复绘制/读取不消费终态或重复结算。

现有生产路径没有可直接复用的文字面板，实施需在 app/显示组合内补充最小文字、进度条及控制显示能力，明确其资源部署和 D3D12/Vulkan 一致输入；不把字体或窗口依赖引入 CPU 模拟，也不预定新 UI 库。必要显示资源纳入安装验证。此处不是通用调试器、编辑器或性能 HUD。不存在历史快照、录制、时间轴、任意时刻回退或历史续算路径。

### 正式 physics 迁移前置

## Risks And Compatibility

- 帧提交最容易混淆的是“就绪”“World 改变”和“已入账”。使用同一 CPU 提交入口和故障注入核对三个阶段。玩家冷却、射线语义及既有 profiling 场景输入沿现役契约。
- 方块身份与区块网格版本具有不同失效范围；用同种方块原位重放、区块内其他格编辑、无变化编辑及版本耗尽验证。排序与准备成本在实际候选测量。
- 依赖接入应沿现有窄 target 和私有头边界。Blender/Groot2 的制作链与游戏运行分开，行为树及 GLB 的坏资产须在可定位的阶段失败。N3 错误不得覆盖原有运行首因。
- 原模型合并导出和一次性 Application 装配均需扩展，不能只给整体模型叠加旋转或重置进度数值。反复重播重点核对长借用、旧 World 缓存、动作身份和 GPU 在途寿命；旧候选测试通过不覆盖这些新增边界。
