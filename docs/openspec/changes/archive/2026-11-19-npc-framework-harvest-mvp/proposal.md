# NPC 框架与耗时采集 MVP

## Why

沿用[下一玩法阶段范围](../../../../scope/project-scope.md#下一玩法阶段npc-与村落演化)，先建立可复用的 NPC 能力与策划行为编排基础，而不是一次实现完整村庄演化或全部职业。当前 [simulation](../../../specs/simulation/spec.md) 已有独立 CPU 会话与角色物理，[world](../../../specs/world/spec.md) 已有受控编辑，[renderer](../../../specs/renderer/spec.md) 已有中立绘制接口；这些基础不等于 NPC、耗时采集或角色资产管线已经实现。

2026-10-20 起，用户选择 B「耗时采集」作为首个 MVP，随后逐项确认下列范围。2026-10-25 将当时已确认的内容汇入本页。2026-11-08 更新前置状态，按用户确认的 [S1 与 F1](decisions.md) 定稿增量规格。

2026-11-16 按用户选定的演示方案扩展 N3：提前提供身体分件驱动的简单行走和采集动作，并增加单人主演示、双人争抢对照、开始/暂停/从头重新演示及进度和结果提示。此前静态候选的实现与验证不证明本次扩展已完成；新增工作见 [任务](tasks.md)。

## What Changes

### 三个并行工作节点

| 节点 | 职责 | 交接关系 |
| --- | --- | --- |
| N1 NPC 实体与动作基础 | 实体装配与生命周期、真实移动、耗时采集、产出及取消/结果 | 动作可脱离行为树调用；负责 SimulationSession/Application 的最终接线 |
| N2 行为树与策划工作流 | BehaviorTree.CPP、策划树资产、每 NPC 运行状态、节点绑定与诊断 | 按共同约定的接口先行，不必等待整个 N1 完成；真实动作接入由 N1 对应能力交付解除阻塞 |
| N3 角色资产与动作表现 | Blender/GLB/cgltf、身体分件与关节轴、共享网格、程序旋转及演示反馈 | 可用约定的显示数据独立验证，最终接真实实体和动作；不接蒙皮或动画库 |

B 是 N1+N2 的联合验收场景，不新增第四个开发节点；模拟动作的 mock 只能支持先行开发，不能替代真实 World 闭环。N3 提供游戏内可见验证，不替代 CPU 正确性。先约定动作请求/结果、实体身份与显示数据的共同交接面，再分别推进内部实现，避免三个节点同时改写会话编排。这里的并行是开发分工，不授权运行时并发访问 Registry，也不指定新的 M 阶段编号。

### 实体表示与首批行为范围

- **行为接口与数据分开：** 采用薄的 `LivingEntity -> Player / Mob` 行为门面，关联 EntityId；允许子类对行为接口提供自己的实现，但公共动作规则仍经统一校验。位置、运动及其他玩法状态由 ECS 组件唯一持有，不在门面复制，不长期保存组件地址。`LivingEntity` 名称不自动要求本阶段实现生命值或战斗系统。
- **显式装配：** 装配流程安装共享组件及 Player/Mob 各自特有的组件；Player 可以挂载专属 ECS 组件。系统按组件组合处理数据，C++ 继承不自动安装组件，也不产生 ECS 基类多态查询。组件、身份、短借用、查询后结构修改和失败边界沿用 T5，不另造一套 ECS。
- **人类：** 完成下面的 B 耗时采集闭环。**僵尸：** 有独立实体定义、静态外观与 Idle 行为树，验证创建、移除及状态隔离；本阶段不实现感知、追逐或攻击。
- **能力扩展：** 底层动作负责校验、推进、取消与结果，行为树负责选择与组合。职业未来由策划数据与树表达，不以伐木工、建筑工人等职业派生 C++ 实体类。新增组合可复用已有能力，但全新的玩法机制仍需开发底层能力；本阶段打通“新增能力、注册节点及参数、编辑器可用、运行诊断”的扩展流程，不追求一次覆盖所有职业。

### MVP B：指定方块的耗时采集

人类 NPC 从场景配置或树输入取得一个指定资源方块，移动到附近合法工作位置，持续采集，真实 World 移除成功且确实改变有效目标后，仅向该 NPC 结算一次产出。完成或失败后进入 Idle，不自动搜索下一目标或重试；目标坐标不写死在 C++ 行为节点里。

| 主题 | 本阶段已确认边界 |
| --- | --- |
| 适用主体 | 新耗时采集仅用于 NPC；玩家保留现有即时破坏路径、冷却与交互规则，不迁移玩家采集 |
| 耗时参数 | 有效耗时 = 方块基础采集秒数 / NPC 采集效率；初版效率默认 1.0。参数须有限且为正，不可采集单独表达，不以负数或无穷值充当标记；不附带职业、工具或技能系统 |
| 进度与时间 | 进度属于当前动作实例，按模拟时间推进；取消、切换任务或中断清零，再次采集从零开始。游戏暂停只冻结进度，不算取消，不累计暂停期间的现实时间 |
| 目标失效 | 原方块被移除或替换使旧动作失效，不能接着采集替换后的方块；开始、推进及提交的有效性由动作层检查 |
| 产出规则 | 每种可采集方块配置一个资源 ID 与固定数量；无采集规则即不可采集。资源 ID 不要求等于 BlockID，不做随机、多产物或工具加成 |
| 资源存放 | 产出记入采集 NPC 的简单资源计数器（资源类型到数量）；不做格子、容量、重量、掉落拾取、仓库或存入动作 |
| 争抢与结算 | 不预约目标，各 NPC 独立累计；先真实成功移除目标者获产出，其他动作失败。Rejected、Unchanged、目标失效或重复推进均不得产出，不能以“请求已发送”当成功 |
| 移动范围 | 受控、平坦且可达的场景，直达附近工作点，经真实角色物理移动而非传送，不把 NPC 放入目标方块。受阻应明确失败/停止，不无限顶墙；到达有效位置后才采集 |
| 碰撞范围 | 只碰撞地形；NPC 可与其他 NPC、玩家重叠，不实现角色互挡、推挤或局部避让 |

移动是 B 的真实依赖；A「定点巡逻」与 C「僵尸追击攻击」留在本轮范围之外。采集的[提交顺序](specs/simulation/spec.md#requirement-ordered-harvest-commit-after-player-edits)和[入账失败边界](specs/npc-entities/spec.md#requirement-prepare-resource-credit-before-removing-a-block)按增量规格执行。2026-11-09 确认采用[稀疏单格版本和会话有效规则时间](decisions.md#后续选型)。

### N2 策划工作流与运行诊断

- **工具选择：** BehaviorTree.CPP 作为运行时，Groot2 FREE 作为离线可视化编辑器；本阶段不依赖付费 PRO 功能或编辑器实时监控连接。实施候选固定 4.9.0 与提交 `3ff6a32ba0497a08519c77a1436e3b81eff1bcd6`，依赖及验证身份见 [verification](verification.md)。
- **策划表达：** 支持节点组合、参数及 BehaviorTree.CPP 内建的简单表达式，限算术、比较、逻辑和黑板赋值；不引入 Lua 或通用脚本运行时。表达式不能绕过动作校验直接修改 World/ECS，黑板不成为库存等玩法数据的第二权威。
- **接入与校验：** 导出项目自定义节点及参数描述供编辑器使用；装载时明确报告未知节点、非法参数、缺失子树等错误，不静默退回 Idle 掩盖坏资产。每 NPC 的树运行状态、黑板及动作进度独立。
- **装载方式：** 仅启动时加载树，修改后重启生效；本阶段不做手动重载、自动监视或运行状态迁移。
- **诊断方式：** 保留状态变化日志和按需只读快照，能够关联 NPC、当前节点、目标、动作、进度、资源及失败原因；不逐帧刷日志，观察不推进模拟。下述演示增加面向观察者的控制和进度/结果提示，不扩为通用调试面板，也不以编辑器连接作为游戏运行前提。

### N3 Micro Voxel 分件角色与简单动作

Blender 制作 micro-voxel 外观并导出 GLB，游戏以 cgltf 解析，校验并转换为项目角色数据，再交给 D3D12/Vulkan 绘制；导入库不代替项目网格转换、材质解释或 GPU 资源管理。

- 在已实现的静态角色管线上保留身体分件、局部变换和肩/髋旋转轴，通过独立刚性部件的程序旋转表现摆腿、摆臂和采集动作；支持实体世界位置、整体朝向、模型资源共享及实例创建/销毁。行走跟随实际水平位移，采集跟随真实动作阶段和有效耗时，暂停冻结姿态。仍不做骨骼、GPU 蒙皮、动画片段库、IK 或肘膝弯曲。
- 采用顶点色、硬边法线及简单光照，不要求 UV/颜色贴图，不扩为完整 PBR、透明混合或法线贴图管线。使用独立的浮点角色网格表达，不复用基础方块的整数 `BlockVertex3D` 或改变世界网格语义。
- 实施方提供能辨认人类和僵尸的简化 micro-voxel 验证模型，交付可编辑 `.blend` 源与实际从 Blender 导出的 GLB，验证完整制作/导入链。模型是技术验证资产，不代表最终美术品质验收，也不要求用户先交付正式角色。
- 两个现代后端均接入同一角色输入；GL 只做受影响回归，不承诺本次角色特性等价移植，也不提前退役 GL。

### 可反复观察的采集演示

演示默认展示一名人类从行走、到达工作点、耗时采集到产出结算的完整过程；可切换为两名人类争抢同一资源的对照场景。Idle 僵尸放在侧边，不遮挡人类、目标和反馈。视角及资源位置服务于清楚观察，沿用真实地形移动和采集规则，不以播放预制轨迹替代模拟。

演示提供可发现的开始、暂停/继续、从头重新演示和场景切换入口。手动暂停时画面和控制仍可用，模拟、动作进度及姿态均冻结；从头重新演示或切换场景创建干净的新一轮，恢复初始资源和 NPC 状态，不修改旧终态实现“重试”。演示内显示各人类身份、当前动作、目标、采集进度、资源数量与成功/失败原因；仅真实 World 改变且入账完成后提示采集成功，争抢败方不显示获得资源。

本次仅提供从初态重新演示；任意时刻倒退、时间轴、历史录制/恢复、从历史继续模拟及回退后干涉均搁置。演示控制不扩展普通玩法编辑或既有性能场景。当前没有可直接复用的文字面板管线，实现需补充必要的最小显示入口，不预选通用 UI 框架。

### 最小验证与短体验范围

正确性验证仍以 **2 名人类 + 1 名 Idle 僵尸** 为基准，覆盖人类独立目标与争抢同一目标、单次产出、树/动作/资源互不串扰，以及僵尸保持 Idle。它与默认单人主演示分开配置，两者复用同一生产规则；该规模不是大量 NPC 容量或性能承诺。

实施方用真实生产库的自动测试覆盖完整采集规则、取消/暂停/目标失效、重复结算、实体移除、CPU 交接及受影响的构建、资源生命周期和现有玩法回归。真实 World/物理、测试替身与真实 GPU 依据分别报告，不用可见模型或 mock 成功替代规则成立。

人工采用本机 D3D12、Vulkan 各一次短体验，**每后端操作与观察合计不超过 3 分钟，两后端总计不超过 6 分钟**，集中看外观、移动/采集反馈及退出。子场景、重启与配置切换共用对应后端上限，不分别追加；到时未完成项记为未执行，失败如实保留，不为补齐清单自动延长或反复重跑。短体验不证明长期稳定性、罕见故障或正式性能预算，也不授权新增长采样或长时替代测试。

### 未来方向与当前排除

明确保留的后续方向是**有限区域自动寻路、手动行为树重载、通用游戏内只读调试面板**，本阶段不预建其实现。完整职业、村落任务/演化及骨骼动画继续分阶段设计，不能因本页提及而视为已选完整方案。

当前不开展计算服务 owner/client-server 重构、IPC、联网、独立服务器产品或窗口关闭后持续演化；保留当前单进程组合与 CPU/显示分离。完整背包/仓库、掉落物、整树采伐、完整战斗、通用寻路和角色间动力学也不进入本轮。

## Capabilities

以下是本 change 的增量规格及其基线。

- **新增能力。** [npc-entities](specs/npc-entities/spec.md) 负责实体、动作和资源计数，[npc-ai](specs/npc-ai/spec.md) 负责行为树、资产校验与只读诊断，[character-assets](specs/character-assets/spec.md) 负责独立可验证的 CPU 角色导入契约。
- **现有能力增量。** [simulation](specs/simulation/spec.md) 增加 CPU 推进和只读动作/显示交接，[world](specs/world/spec.md) 增加采集定义和目标有效性，[renderer](specs/renderer/spec.md) 增加共享角色分件实例和状态驱动的动作，[module-boundaries](specs/module-boundaries/spec.md) 与 [application-lifecycle](specs/application-lifecycle/spec.md) 分别增加依赖隔离、运行装配和演示控制。各增量沿用同名现役能力；实体身份和借用复用现役 [ecs](../../../specs/ecs/spec.md)。
- **保留的基线。** 玩家即时拆放、冷却和模拟后编辑沿用 [simulation](../../../specs/simulation/spec.md)，独立 `static/walk/edit` 的工作负载和模拟前编辑沿用 [application-lifecycle](../../../specs/application-lifecycle/spec.md)。[物理核心](../../../specs/physics-core/spec.md)算法、基础方块存储/网格、[platform](../../../specs/platform/spec.md)、[foundation-files](../../../specs/foundation-files/spec.md) 与 [telemetry-lifecycle](../../../specs/telemetry-lifecycle/spec.md) 契约继续适用。

## Impact

后续实现的直接影响拟限于 simulation 的 NPC/AI 与采集、world 的必要规则扩展、assets/scene/renderer 的角色数据、app 的组合、根测试及第三方依赖/许可和角色资源部署。保持 CPU 模拟不依赖窗口或具体图形后端，显示不成为玩法权威；沿用现有生产 owner 和 CMake 软硬边界，不预先新增空模块或通用能力框架。

T5 与 M3 已整体验收，T5 主规格已同步并归档，生产交付及必要构建和测试配套已同步主工作区，见 [T5 验收与同步记录](../2026-10-25-m3-t5-ecs-memory/verification.md#2026-10-25-t5生产交付同步主工作区)。NPC 刚体装配沿用 T5 的[显式物理步进顺序](../2026-10-25-m3-t5-ecs-memory/design.md#物理步进顺序)。[physics-core](../../../specs/physics-core/spec.md) 规定的正式迁移已于 2026-11-16 [独立验收](../2026-11-16-promote-physics-module/verification.md)，当前分支已取得迁移源码；NPC 复用此前置成立，历史验收范围保持原义。

[RenderDoc/Tracy 已于 2026-11-07 整体验收并同步主规格](../../integrate-renderdoc-tracy/verification.md#2026-11-07-整体验收通过与主规格同步)。[现行范围](../../../../scope/project-scope.md#下一玩法阶段npc-与村落演化)将 Y9000P 中端与 GTX 1650 低端整机性能验证安排在现代性能工具接入后，已解除两机采样作为玩法实施前硬门槛的旧约束；两档验证与用户结论仍待安排。[旧 benchmark 产品和性能导出已退役](../../../specs/development-profiling/spec.md)，保留独立 `static/walk/edit` 场景。[Fix1 已取消归档](../2026-11-03-m3-t2-publication-fix1/verification.md#2026-11-03-因能力退役取消计划并归档)，历史故障和未完成项沿原记录。NPC 实施仍需设计、依赖就绪及单独授权。

接口、提交和资源机制见 [设计](design.md)。依赖精确身份、配置取值、运行预算与交付资产的输入上限随实现候选核验。

本次修订复用上述能力路径：新增演示控制、可见反馈及刚性分件动作行为，修改原静态角色交接范围，采集规则和现有性能工作负载保持原契约。[RenderDoc/Tracy 计划](../../integrate-renderdoc-tracy/proposal.md)的工具接入不承担此演示面板；本次不恢复性能导出或扩展性能观测产品。文档更新本身不授权代码实施、主规格同步或归档。
