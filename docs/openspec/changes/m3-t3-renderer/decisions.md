# T3 决策

本页维护本 change 的已选设计及其限定身份；批准/冻结只从 [VERIFICATION](../../../verification/VERIFICATION.md) 判读，不据迁移重新选型或扩权。

## M3-T3/D01 先行现代后端

2026-10-07 用户选择方案1：先 D3D12 接管现有玩法，再 Vulkan。优先闭合 Windows 的一条真实生产路径，代价是第二后端仍须独立接入与复验，不能继承 D3D12 成绩。
未选方案为 Vulkan 先行、同夹具双后端实验后再选；历史候选中的“双机”不是当前功能/兼容门槛。

## M3-T3/D02 整体完成门槛

2026-10-07 用户选择方案2：R1–R4、两个现代后端分别完整接管后申请 T3 整体验收，GL 最终退役另立后续节点。
不采用“单现代即 T3 通过”或“先清除全部 GL 才能验收 T3”；双现代工作量较大，但能以两种 API 验证 v1。此选择没有批准切默认、删除 GL 或恢复永久三后端等价。

## 公开稳定与私有演进

2026-10-07 已确认稳定游戏侧 Renderer v1，PImpl 独占一个后端；私有后端可演进。内部 RHI 只在多个真实后端已出现重复且可分离算法/API 责任时提取，不预建空层或选定第三方 RHI。
公开所有权、寿命、失败/线程语义或能力基线改变须受控确认，不能以私有演进为由缩减契约；不承诺跨 MSVC/STL ABI 或二进制插件兼容。

## 现代 alpha-depth 修正

2026-10-09 用户批准现代 alpha < 0.01 discard 像素不写深度；D3D12 不沿用旧 GL 强制 early-depth 的缺陷，旧 GL 对照不改。
不新增透明排序、不改公开三头/签名或材质层编号；局部像素结果仍绑定顺序2历史身份，不回写 R1/旧 GL 成绩。

## 验收环境边界

2026-10-08 已确认当前 M3 功能/兼容仅本机 RTX 5070 Ti，D3D12/Vulkan 分别留实际设备/驱动/能力/呈现及玩法证据。其他 GPU 或第二机器不阻塞本节点。
下一玩法开发前仍须 Y9000P/RTX 3070 Ti Laptop 与 GTX1650 整机候选性能门槛，不能用本机功能结论或旧 GL 数字替代；该选择不减少 A01–A19、工作负载或独立审批。

## 正式视觉参考与性能预算

默认选择现已按2026-10-12用户明确R3批准切为D3D12；批准正文唯一见[全局节点索引](../../../verification/VERIFICATION.md#关键节点)，不是由短测或旧R2入口推定。新游戏配置首次默认编入D3D12，已有缓存不强改；GL保留为显式过渡路径，最终退役另授权，缺能力/资产不fallback。validation/MSAA/公开v1与预算数值不改，未测项目保留风险，Vulkan及整体T3未批准。默认启用后，候选专用POST_BUILD身份仅在out/m3-t3子目录且Benchmark关闭时触发，普通preset不被候选目录约束阻断；候选打包校验不放宽，旧包身份不重写。

2026-10-12 用户选择同版本、同场景的 GL 画面作正式对照，已批准的现代透明深度修正单列，不用它解释其他画面差异。参考截图身份、逐场景差异范围及数值容差仍须确定；此选择不是视觉验收通过。

用户要求先提出预算候选、确认后才正式采集。以下保留提出时的四项比较；2026-10-12 用户已选择 D3D12 的方案 4，未选方案 1–3，不重开选型：

| 候选 | P95/P99 条件 | 取舍 |
| --- | --- | --- |
| 1 严格相对对照 | 各自不超过对应 GL 轮次的 105% | 更紧的回归约束，需受控同条件配对 |
| 2 适度相对余量 | 各自不超过对应 GL 轮次的 110% | 容许更大回归，不单独保证绝对流畅度 |
| 3 绝对门槛 | P95 <= 10 ms、P99 <= 12 ms | 沿用 T2 数值作候选，不继承其批准范围或成绩 |
| 4 双门槛（已选） | 同时满足候选 2 与 3 | 同时限制相对回归和绝对帧时间 |

### D3D12 已选预算口径

同日用户确认帧时间方案 4 及内存 10% 相对回归，并明确同意以下内存口径同步规格。仅用于本机 D3D12 与同版本、同机、同配置、同工作负载 GL 的正式对照；static / walk / edit 各三轮，逐场景、逐对应轮次同时判定全部条件，不混池、平均、挑最好或删除慢帧：

| 指标 | 每轮正式采样段的条件 |
| --- | --- |
| P95 帧时间 | <= 10 ms，且 <= 对应 GL 轮次 P95 的 110% |
| P99 帧时间 | <= 12 ms，且 <= 对应 GL 轮次 P99 的 110% |
| 工作集 working set | 约每秒观测值的最大值 <= 对应 GL 轮次同口径最大值的 110% |
| 私有提交 private bytes | 约每秒观测值的最大值 <= 对应 GL 轮次同口径最大值的 110% |

两项内存各自判断，不相加、不取平均或分位数；这是正式采样段内的观测最大值，不是瞬时或整个进程生命周期峰值，不包含显存、启动阶段，也不叠加 T2 的绝对内存上限。帧时间不以平均 FPS 代替 P95/P99，CPU/GPU/present 分位数不相加。

本轮只确定帧时间与进程内存硬预算；启动/首次可操作时间及其他性能指标继续如实观测，缺失具名，不新增其数值通过门槛。不可恢复故障、协议无效、泄漏或隐性降低画面/工作负载仍不能因预算满足而豁免。T2 的既有预算、前台适用条件、成绩及下一玩法前的中低端整机门槛保持原义，不自动移用；Vulkan 的预算须另确认，不继承本次选择。

正式观测协议仍以 [项目范围](../../../scope/project-scope.md#性能目标与测量约束) 为依据；同版本 GL 配对正式基线尚未建立，不把 T2 的短协议或复测授权带入。预算确认时仅同步规格、不启动正式采集；快速协议检查、旧数据消费者复核、构建通过或用户报告的 15 分钟无异常均不替代正式预算对照。后续本轮执行范围按下节用户追加决定，不将未执行的九轮重新列为本轮待启动工作。

### 本轮 R2 短采样收口与风险接受边界

2026-10-12 用户先确认同一 Release004 的 GL/D3D12 正式九轮安排，后明确取消：72 分钟过长，仅给 5 分钟，改为两个后端短采样比较后收口 R2，并要求文档标记风险。此次决定替代本轮长采样执行安排，不改变已选预算数值、不补造正式通过，也不取消其他阶段既定门槛。

实际按原生 quick 协议先 GL 后 D3D12，static/walk/edit 各一轮、各 10 秒预热+10 秒采样；同一游戏/资源、1080p/4x/VSync-off、allow-unfocused，未自动复测。用户同时报告本轮提供的 Release004 人工核查全部通过，按用户反馈记录，不代填逐项原始日志或数值视觉容差。实际结果及人工反馈见 [本 change 验证正文](verification.md#r2-短采样收口与保留风险)。

本轮 R2 工作按此范围收口；完整技术验收仍不得整项勾选。正式预算的长采样/三次重复、罕见卡顿与持续内存增长未证明；静止场景两后端实际焦点比例不一致，不能作严格同条件性能结论。正式视觉参考的完整身份与数值容差、未覆盖原生故障/干净机器部署、Win32 1175/Fix1 继续具名保留。后续补测另授权，不恢复九轮、Fix1、切默认或推定 R3/T3 整体验收。

同日用户选择“隔离进程的受控原生故障，加有限注入”：窄私有诊断工厂链接真实门面状态/后端，以自有设备移除及自有队列 gate 验证原生失效/在途等待，并分别记录分配与提交 HRESULT 注入。相较仅注入或后续人工配合，它增加明确诊断所有权与真实同步取证；不触发整机 TDR、不改公开 v1/默认后端/恢复语义，不将受控移除称为自发硬件事故，也不据此降低 A13/A14 或关闭整组验收。
