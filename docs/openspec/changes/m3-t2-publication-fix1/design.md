# Fix1 目标机制与定位边界

## Context

公开行为和允许失败状态由[现役 foundation-files](../../specs/foundation-files/spec.md)维护，目标/验收见 [delta](specs/foundation-files/spec.md)。当前用户暂停，F1 部分交付、F2 根因未定位、F3 未选替代机制；本页不是继续执行诊断的授权。

当前 telemetry 在 Publish 前已关闭写流，runner 读状态使用兼容 share=7。普通 closed-target、关闭阻塞读者后恢复及共享读者阶段均有失败，不能预设漏 close、SDL/SDK 或 runner 是原因。历史主工程 40 进程中四个失败缺 numeric_win32，不能事后都改写为 1175；新诊断捕获的明确 1175 与旧批次分开。原事实入口为 [Issues 附录](../../../issue/issues.md#附录)及[Fix1 目标与暂停范围](proposal.md)，其中命令/结果只具点时意义。

无 API 日志 Debug 控制批 files/export 为 10/20、19/20；开启 API 日志 Debug 两项各 20/20、关闭日志 Release 两项各 20/20。观察改变时序的可能性未排除，不能把诊断批次变绿当修复。完整主测试 Debug 62/63 启用通过（原 world.allocations 禁用），Release 63/64，均 files 失败；runner 新终态拒绝用例有既有通过结果，但不关闭 V01-V07 整组。本轮没有重跑这些结果。

## Technical Approach

### 所有权、发布与失败

调用方持有临时流并完成关闭；foundation 只处理同卷路径发布，不拥有长期状态读者或多写者锁。telemetry 拥有 session 数据与输出目录；runner 拥有其状态读句柄与协议消费。各方显式成对关闭，诊断工具不能改变共享标志来规避待定位故障。

当前 ReplaceFileW 无备份/flags=0，ERROR_FILE_NOT_FOUND 后只试一次不覆盖 MoveFileExW。该条件可能涉及源缺失而不只是目标缺失；不增加 exists→replace 的 TOCTOU 分支。若未来改变机制，先提供已证实失败与契约对照，不将非 POSIX rename 实验当已选替代。成功是新路径完整内容与旧句柄旧快照；失败可能涉及目标路径消失/改名或属性合并，不能承诺通用回滚。

发布失败立即锁定原错误；后续存在性/属性/hash 查询只补观察，查询自身失败具名，不能替换原 code。状态序列先 exporting、再结果文件、后 finished；最后发布失败允许 tmp=finished/yaml=exporting、CSV/summary 已存在，内存 completed 也可能仍真。对外成功须依真实终态/退出，不设计全输出事务或失败时自动恢复内存为前提。

### F1 诊断完整性

最小内部上下文包括 run ID、UTC、PID/TID、配置、源码/exe SHA、案例/状态、循环下标、API/flags、预期成功/拒绝、原数值 code/category、源/目标路径、本测试持有句柄/share、前后存在性/属性及可获得内容摘要。包外记录诊断，不新增公共 Win32 类型或修改状态 schema。

覆盖全部路径而不是只扩共享循环 catch；关联 API 事件与对应进程/线程/操作，外层区分发布/断言/序列化/写流/采集失败。计划进程、实际尝试、单次 operation 的多个 API 与预期拒绝分别计数。现有采集器删单条 API/终事件仍可能 complete 的缺口必须先修复并负向自测，complete 不是完整性证明；缺码旧结果只保留限制。

### F2 有界复现与因果定位

恢复授权后才在全新编号输出下构建真实两配置测试库/程序，先无追踪控制再有追踪诊断；每配置每测试首批最多 20 独立进程，捕获后可早停且报告实际次数。不在失败内部重试，也不无限扩大批次；未复现/权限不足保持未定位，提出下一项能区分原因的检查。

文件 I/O 追踪按测试输出目录收全部进程访问，不只筛测试 PID；关联 Create/Open、Rename/Delete/Disposition、Close 的访问/共享/结果及可得栈，覆盖失败前后时间线，保留原生记录。句柄快照未命中不排除瞬时句柄。先核对实际 caller/test/runner 的关闭及文件/目录属性、ACL、卷/文件系统、重解析，再观察安全软件/同步/过滤事实，不因组件存在归因。

同身份/参数在原 F: 工作区与全新普通非同步目录对照；跨工作区/磁盘或驱动/管理员追踪需另获权限。原 Process Monitor 请求已撤销，不自动启动、不关闭 Defender/加排除/卸载过滤驱动/强关其他进程/提升产品权限。采集限测试目录，不将无关用户数据写入交付。

### F3 最小机制与同步

有证据的句柄寿命/API用法/顺序问题在所属模块最小修补，用原复现或受控夹具给出修复前失败/修复后成立。涉及发布机制、读者行为、备份/恢复、多文件协议或环境例外时先做变更设计和真实选型，不借 workaround 隐藏失败。首次创建竞态由受控同步建立，不用 sleep 碰概率；这只是测试确定性，不新增多写者服务保证。

不增加线程、全局锁服务或输入/GPU 依赖。即使源错误对象/诊断线程各自保留，跨进程时间线仍需实际 UTC/关联事实，不能靠局部序号推定其他进程责任。调试和最终候选是不同身份，最终验收不启 API/外部追踪来改变条件。

## Decisions

本轮没有足够根因证据选定新的 Win32 API、备份/恢复或环境例外，因此不创建伪决策表/decisions.md。现有窄 API 修补和不降低契约的边界继续有效，不重新选型。确有重要行为取舍时按 [scope 选型规则](../../../scope/project-scope.md#方案决策与选型规则)给出 3-4 个真实可行方案及失败状态/兼容性/成本/迁移，再等待确认；可完成 M3-I2 不代表 M3-I1 也可关闭。

## Risks And Compatibility

1175/1176/1177 的记录传播可用受控失败证明；真实文件后状态只在真实 API 触发时报告，未触发的晚期错误不标实测通过。无追踪也不证明没有外部观察者；API 日志与 Process Monitor 可改变时序。统计绿结果、已存在 CSV、T2 批准、CLI validate 与文档迁移均不是根因/可靠性关闭依据。

必要证据留 `out/m3-t2/fix1/<新批次>/`，只有解释关键结论的小型身份/摘要按验证归属保存；不逐尝试新增文档报告，不覆盖 S3/S5/GLFW 包或历史失败。保留命令、工具/环境/源码/库/exe/包 SHA、实际次数/退出、追踪入口与真实现场，诊断与交付身份分开。M3-I3 的历史索引/执行路径及用户“无所谓”保留，不扩大本 change。
